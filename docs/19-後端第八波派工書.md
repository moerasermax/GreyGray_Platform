## 5. 工作包

### BE-22　本機開發環境（`D:\GreyGray`）　🔴 先跑這包

**相依**：無　**獨佔**：`ops/**`

**為什麼這一包排第一**：**D 階段 0/7，而 FE-12 是它的第一步。**
FE-12 從第三波等到現在，等的一直是「有一個真後端可以打」。
YC 上的服務只綁 loopback（那是對的），所以開發機連不到——要在開發機自建一組。

**必做**

1. **裝在 `D:\GreyGray`，不要用 C 槽。**
   `ops/install-environment.ps1` 的三個路徑本來就是參數：

   ```powershell
   .\ops\install-environment.ps1 `
       -InstallRoot 'D:\GreyGray' `
       -PostgreSqlDataRoot 'D:\GreyGray\PostgreSQL\data' `
       -PostgreSqlWalRoot 'D:\GreyGray\PostgreSQL\wal'
   ```

   **不要改腳本的預設值**——正式機 YC 仍然用 `C:\GreyGray`，那是對的。
   如果腳本裡還有別的地方把 `C:\GreyGray` 寫死（沒走參數），**那就是要修的 bug**，
   修它，並且在自驗報告裡列出你改了哪幾行。

2. **跑起 PostgreSQL 17 與 Garnet**，本機的可以綁 loopback（開發機自己用）。
3. **跑一次 migrations**：`ops/invoke-migrations.ps1`（或它的等價步驟），
   把 `0001_` 到 `0014_` 全部套上去。
4. **跑起三個 Host**：`GreyGray.Api.Storefront`、`GreyGray.Api.Admin`、`GreyGray.Worker`，
   確認 `/health` 回得了。
5. **`ops/verify-environment.ps1` 要能對本機這一組回 PASS**——
   如果它寫死了正式機的服務名或路徑，讓它吃參數。

**做法要點**

- **不要動正式機 YC 的任何設定。** 這一包只碰開發機。
- **不要把密碼放進命令列**（會進 log、進事件檢視器、進 `Win32_Process`）。
  走 `--optionfile` 或環境變數，本機的秘密檔也收緊 ACL。
- 本機這一組是**開發用**，測試資料會很髒——這是刻意的，
  正因為髒所以不能拿正式機來做（D3 的第五條成立條件就是「資料能重置」）。

**自驗（寫進 `.dispatch/reports/BE-22.md`）**

1. 安裝指令的完整輸出（密碼遮蔽）
2. `Get-Service` 或行程狀態：PostgreSQL 與 Garnet 都在跑
3. `Get-NetTCPConnection -LocalPort 5432,6379 -State Listen` 有 listener
4. `pg_isready` 的回應、Garnet 的 `+PONG`
5. migrations 跑完的輸出，`0001_`～`0014_` 都套上了
6. **三個 Host 的 `/health` 實際回應**——這一條是 FE-12 能不能開工的判準
7. `ops/verify-environment.ps1` 對本機回 PASS 的輸出
8. `git diff --name-only` —— 只有 `ops/` 底下（本機安裝的東西不進版控）

### BE-21　帶回→待出貨接線 ＋ `OrderLineId` 改必填

**相依**：無（BE-19 已經讓事件帶出 `OrderLineId`）　**獨佔**：見 §3

**兩件事，都很小，但第二件是帳務相關的。**

#### 第一件：接線

第六波驗收發現這條線是斷的，第七波 BE-19 補上了事件欄位，**但沒有人訂閱它**：
`IOrderingGoodsReceipt.RecordGoodsReceivedAsync` 已經存在、已實作、已 DI 註冊，
**全 repo 沒有任何呼叫點**。

在 `Ordering.Infra` 加一個 `IIntegrationEventHandler<GoodsReceived>`，
呼叫既有的 port。比照 Inventory 與 Ledger 的做法
（`Inventory.Infra/ModuleRegistration.cs` 的 `AddIdempotentIntegrationEventHandler<...>`）。

**不必改 `Ordering.Core`**——那個 port 已經夠用，而且 Core 不在你的 allow。

#### 第二件：`GoodsReceived.OrderLineId` 改必填

現在是可選參數（`= default`），**漏傳會靜默送空值而且照樣編得過**。
這個事件從沒上過正式機，現在改沒有相容性成本；之後才改就要發 v2。

**為什麼值得改**：這是帳務相關的欄位。漏傳的後果是
**訂單永遠不會轉待出貨，而且不會報錯**——正是這個專案一直在避免的那種故障。

改成必填之後編譯器會列出所有建構點，逐一補上。那是編譯期抓得到的工。

**自驗（寫進 `.dispatch/reports/BE-21.md`）**

1. `dotnet build .\GreyGray.slnx` 0 error 0 warning
2. `.\ops\test.ps1` 全綠，說明新增幾條（**前景跑，不准丟背景**）
3. `git diff --name-only` —— 只有你擁有的路徑
4. **端對端**：Procurement 帶回 → Ordering 收到 → 訂單轉 `ReadyToShip`，
   用真 PostgreSQL（Testcontainers）跑，不要只做單元測試
5. **最後一條 line 才轉**：兩條預購 line，只帶回一條時**不**轉待出貨的測試
6. `grep -n 'OrderLineId' src/Modules/Procurement/**/ProcurementContracts.cs`
   證明它不再有 `= default`

## 6. 自驗與總驗收

### 每一包交付時

**寫進 `.dispatch/reports/<你的包名>.md`**，三個標頭一字不差：

```markdown
## 指令與輸出
## 逐條自驗
## 我發現但沒做的事
```

缺任何一個標頭，`audit-dispatch.sh` 第 ⑧ 項會擋下 Leader 收工，你的交付會被退回。

**「我發現但沒做的事」沒有就寫「無」。** 這一項不是形式——
前五波每一波都靠它抓到真問題（缺口、契約矛盾、別包的瑕疵）。

### 總驗收（整合者做）

1. `bash .dispatch/audit-dispatch.sh` —— 八項全過
2. 越界檢查，區分同波越界與跨波接線
3. 自己重跑 build 與測試，**不採信自述**
4. 鐵則掃描；migration `SET ROLE` ＋ owner 斷言 ＋ 可重跑 ＋ 一號一檔
5. **交付方沒有提到的問題**——前三波的重大發現都是複驗才看到的
