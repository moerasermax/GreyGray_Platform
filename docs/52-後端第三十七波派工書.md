### 0.1 為什麼要做

契約從 M1a 起就有 `DeliveryMethod.ConvenienceStore` 與 `CheckoutRequest.convenienceStoreCode`，但**從來沒有接電子地圖**：

### 0.2 綠界電子地圖（ADR-038 已查證，照做）

- 地圖：瀏覽器以 form POST 到 `Logistics:ECPay:MapUrl`（正式 `https://logistics.ecpay.com.tw/Express/map`、測試 `https://logistics-stage.ecpay.com.tw/Express/map`）。
  欄位：`MerchantID`、`LogisticsType=CVS`、`LogisticsSubType=UNIMARTC2C`、`IsCollection=N`、`ServerReplyURL`、`ExtraData`（≤ 20 字）；`Device`（`0` 電腦、`1` 手機）選填。**不帶 `MerchantTradeNo`。**
- **請求與回傳都沒有 CheckMacValue**——回傳可以被任何人偽造。所以後端只信自己發的選店票。
- 客人選好後，綠界**經客人的瀏覽器**把 `MerchantID`、`MerchantTradeNo`、`LogisticsSubType`、`CVSStoreID`、`CVSStoreName`、`CVSAddress`、`CVSTelephone`、`CVSOutSide`、`ExtraData` 以 form POST 到 `ServerReplyURL`。
- ★ **這是從 `ecpay.com.tw` 發起的跨站頂層 POST**：`gg_cart` cookie 是 `SameSite=Lax`（第 1241-1250 行 `SetCartCookie`），**跨站 POST 瀏覽器不會帶**。
  所以回傳端點**不准讀、也不准發任何 cookie**，只靠選店票找到購物車。303 導回前台之後是同站 GET，cookie 會回來。

**C1 設定**（一個可測的讀取函式）
- `Logistics:ECPay:MerchantId` **空白 → 「沒有設定」**：開機照常；`cvs-map-sessions` 回 `503 logistics.not-configured`；回傳端點 303 帶 `not-configured`。

- ★ **在組合根就驗**：由掛端點的入口（`MapM1aStorefrontEndpoints` 或 `src/Hosts/GreyGray.Api.Storefront/Program.cs` 的註冊）呼叫讀取函式，壞設定在 Host 起來時就炸，不是等第一個請求才炸。（覆驗更正）

**C0 OpenAPI metadata**（覆驗更正）
- 三條端點加 `.Accepts`／`.Produces`（request body、`CvsMapSession`、`CvsStoreSelection`、303／404／503），讓 live 文件形狀跟契約一致。
  `check-openapi` 的 M1a 模式只比 method＋path（`ops/OpenApiContractGate/Program.cs` 第 129 行自己印著「本模式未執行完整 schema 語意比對」），綠燈證明不了形狀。

**C2 選店票**（`IDistributedCache`）
- 票：`RandomNumberGenerator.GetString` 從 `[A-Za-z0-9]` 取 **20 個字**（綠界 `ExtraData` ≤ 20；只用英數，避免 `-`／`_` 被綠界擋）。
- 值（JSON）：購物車 id、狀態（`Pending`／`Selected`）、建立時間、到期時間、門市代號／名稱／地址／是否離島。
- 時間一律經 `IClock`；**`now >= expiresAt` 就算過期**（不要只靠 Garnet 的 TTL，另外自己比）。快取的 `AbsoluteExpiration` 設成同一個到期時間。
- `Pending`：建立後 **15 分鐘**。選好之後改成 `Selected`，到期時間**重設為選好之後 60 分鐘**（客人回到結帳頁還要填別的東西）。
- 快取鍵用**票的 SHA-256**，不要把票明文放進鍵（照 `src/Platform/Sessions/DistributedSessionStore.cs` 第 110-114 行對 session token 的做法）；鍵名寫進報告。（覆驗更正）
- 票的格式（恰好 20 個英數）由**一個共用函式**驗，C4、C5、C6 三處都用它。（覆驗更正）

**C3 `POST /v1/logistics/cvs-map-sessions`**
- 匿名可用。購物車 id 用 `GetOrCreateCartId`（這裡可以發 cookie）。
- 回 `CvsMapSession`：`selectionId`＝票、`method`＝`POST`、`action`＝`MapUrl`、`expiresAt`；`fields` 依序 `MerchantID`、`LogisticsType=CVS`、`LogisticsSubType`、`IsCollection=N`、`ServerReplyURL`、`ExtraData=<票>`，`device` 有帶才加 `Device`（`Desktop`→`0`、`Mobile`→`1`）。
- **不要冪等鍵**（契約沒有）：多按一次就是多一張票，無害。
- 回應加 `Cache-Control: no-store`。

**C4 `POST /v1/logistics/cvs-map/reply`**——依序驗，第一個不過就 303 帶那個代碼
1. 手動讀 form（§0.4）。**不讀 cookie、不發 cookie。**
   `ReadFormAsync` 丟例外（不是 form 的 Content-Type、壞掉或超過上限的 form）→ `invalid-reply`；**請求被取消（`RequestAborted` 已取消）的 `OperationCanceledException` 不要吞**。（覆驗更正）
2. 沒設定 → `not-configured`。
3. `ExtraData` 不是 20 個英數 → `invalid-reply`。
4. 讀快取丟例外（Garnet 掛了）→ `unavailable`，**記 log、不回 500**。
5. 票不存在或已過期 → `expired`。
6. 票已經是 `Selected` → `already-used`。
7. `MerchantID` 或 `LogisticsSubType` 與設定不同 → `invalid-reply`，**票維持 `Pending`**（偽造的回傳不能把票燒掉）。
8. `CVSStoreID` trim 後 1-20 個英數；`CVSStoreName` trim 後 1-50 字；`CVSAddress` trim 後 1-200 字；三者都不准含控制字元 → 不過就 `invalid-reply`、票維持 `Pending`。
9. 通過：寫回 `Selected` ＋ 門市資料；`CVSOutSide == "1"` 視為離島。寫入丟例外 → `unavailable`。
10. **303**（不是 302：`Results.Redirect` 預設 302，要自己設 `StatusCodes.Status303SeeOther` 與 `Location`）到 `{Storefront:PublicOrigin}/checkout?cvsSelection=<票>`；失敗是 `?cvsSelectionError=<代碼>`。
    導回網址用 `BuildPaymentResultUrl` 同一套 `Storefront:PublicOrigin` 讀法（抽共用）。**門市名稱、地址不准放進網址。**
    `Storefront:PublicOrigin` 缺或壞是**部署錯誤**，照 `BuildPaymentResultUrl` 直接炸——這是這條端點唯一允許的 500（付款完成頁也靠它；正式部署 `ops/deploy.ps1` 第 46-77 行已強制檢查）。測試設定裡要給這個鍵。（覆驗更正）
- 已知、接受：讀後寫不是原子操作，同一張票兩個回傳幾乎同時到可能都成功、後寫的蓋掉前寫的。票是 119 bits 的秘密、只在客人自己的瀏覽器裡，Leader 接受；**寫進程式註解**，不要為此加鎖。

**C5 `GET /v1/logistics/cvs-selections/{selectionId}`**
- 讀 `gg_cart` cookie，**讀不到就 404、不發新 cookie**。
- 票格式不對（共用函式）→ 404、**不查快取**；票不存在、過期、還是 `Pending`、購物車 id 不同 → **同一個 404**（不區分，免得被拿來猜票）。
- 回應加 `Cache-Control: private, no-store`（內容跟著 cookie 走）。
- 快取丟例外 → 讓它走既有的例外處理（這條是前端 fetch，不是客人看到的頁面）。

**C6 結帳帶選店票**
- `CompleteCheckoutInput`（第 1665-1670 行）加 `string? ConvenienceStoreSelectionId`。

- ★★ **解票放在 `ExecuteIdempotentAsync` 的 `work` 裡，不是在它之前**；冪等指紋要含 `ConvenienceStoreSelectionId`、**不含**解出來的名稱地址。
  否則：同一把 key 已經成功下單，60 分鐘後票過期，客人網路重送 → 應該拿到原訂單，卻會拿到 422。

- 解票：狀態 `Selected`、同一台購物車（`GetOrCreateCartId` 那一台）、未過期 → 用 `request with { … }` 把代號、名稱、地址放進去（**票的代號蓋過客人送的 `convenienceStoreCode`**）。
  任何一項不符 → `Result.Failure("checkout.store-selection-expired", "門市選擇已過期，請重新選擇門市。")`，在任何副作用之前。
