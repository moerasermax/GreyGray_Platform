## 0. 事實（2026-09-30 查證，行號以前端 HEAD `ba3450a` 為準；對不上就停下來回報）

### 0.1 契約（ADR-041）

- storefront `Category` 有選填 `parentId`（`Id | null`），後端照寫不省略；`GET /v1/categories` 列「自己或任一直接子分類有可售商品」的分類，清單**對父分類封閉**（清單裡的子分類，它的父分類一定也在清單裡）。
- storefront `GET /v1/products` 有選填 `includeDescendants`（boolean，預設 `false`）：`true` 時比對「這個分類或它的直接子分類」。
- admin `CategoryInput` 有選填 `parentId`；**PATCH 是整筆取代**——省略或 `null` 就是根分類。所以對話框**每次都要送 `parentId`**，否則只改名稱會把子分類打平成根分類。
- 固定兩層：`parentId` 只能指向根分類；已有子分類的分類不能被設成子分類；不能指向自己。POST 與 PATCH 違反都回 `422`，錯誤碼對應（ADR-041、本樹 `docs/api/openapi.admin.yaml` 第 1266 行附近）：
  - `catalog.invalid-parent-category`：上層分類不存在、不屬於同一個租戶、或指向自己
  - `catalog.category-depth-exceeded`：上層不是根分類，或自己已經有子分類
- 產生出來的型別裡 `parentId` 是**選填**（`parentId?: Id | null`；storefront `Category` 的 required 只有 `id`、`name`）——**`undefined` 一律當 `null`（根分類）處理**。
- ⚠ ADR-041 內文寫的「FE-54」＝**本包 FE-55**（第四十二波修正包佔用了 FE-54，包名順延一號）。

### 1.2 分類樹共用邏輯（前台新檔，例如 `frontend/apps/storefront/app/_lib/categoryTree.ts`（新檔））

- **防禦性**：`parentId` 是 `undefined`／`null` → 根分類；子分類的 `parentId` 在清單裡找不到、或指向的上層本身不是根分類（資料壞掉的第三層）→ 當根分類列出（不丟例外、不遺失）；只認兩層，不遞迴。

- 前台三處（抽屜、分類頁、首頁）都用它，不要各寫一份。後台引用不到前台的 `_lib`，後台的分組另寫在 `frontend/apps/admin/app/(dash)/catalog/_lib/`（allow 已涵蓋）。

- 保留 FE-54 的預取、快取、失敗重試、loading 佔位（抽屜打開時不能再出現跳動）。**快取繼續存平面清單**（`mobileNavMenu.test.tsx` 用平面清單測 `createDrawerCategoriesCache`）。

### 1.4 分類頁（`frontend/apps/storefront/app/(shop)/categories/[categoryId]/page.tsx`）

- 依 1.2 判斷這個分類是父（清單裡有它的子分類）還是子。
- **父分類**：標題下方列子分類 chip——用 `next/link` 做的文字 pill（≥ 44px 高），**不要**用 `CategoryChipLink`（它是 button＋router，測試環境渲染不了）；新元件放在 `(shop)/categories/` 底下。商品用 `includeDescendants: true`（第一頁與 `InfiniteProductGrid` 的 `query` **都要帶**，否則捲動載入的第二頁會變回只查父分類）。建議把「這個分類的查詢參數」寫成純函式，T4／T5 測它。
- **子分類**：標題上方一個回上層的連結（「← ○○」）；商品查詢維持 `categoryId` 相等比對。
- 404 判斷維持「在不在清單裡」。

### 1.5 首頁分類列

- `CategoryRail` 只列**根分類**（`(shop)/page.tsx` 傳入前或元件內用 1.2 的「只取根分類」純函式過濾，擇一，不要兩邊都做）。`CategoryChipLink.tsx` 不需要改。

### 1.6 後台

- `CategoryDialog`：加「上層分類」下拉，用 `@greygray/ui/admin` 的 **`Select`**（不要原生 `select`），`placeholder="（無，作為根分類）"`，送出時空字串轉 `null`；選項＝所有**根分類**，**排除自己**；編輯中的分類若**已有子分類**，下拉停用並用 `Field` 的 `hint` 顯示「這個分類底下已有子分類，不能再設為子分類」（`Field` 不會自動接 `aria-describedby`，要自己在 `Select` 上帶 `${htmlFor}-hint`）。
  - body **一律帶 `parentId`**（從既有值預填；新增時預設 `null`），冪等 payload 也要包含它。
  - 對話框需要完整清單才能列選項與判斷「有沒有子分類」：由 `categories/page.tsx` 把已載入的清單傳進來，不要在對話框裡另打 API。
  - 422 的兩個錯誤碼照既有 `apiErrorMessage` 顯示；**不在前端重寫規則的錯誤訊息**。
- `categories/page.tsx`：表格加「上層分類」欄（根分類顯示「—」）；列的順序改成「根分類，後面緊接它的子分類」，子分類名稱前加縮排或「└」標示。
- 商品表單（`_components/ProductForm.tsx`）與商品列表篩選（`frontend/apps/admin/app/(dash)/catalog/page.tsx`）的分類下拉：子分類的選項文字改成「父 › 子」（不同父分類底下的同名子分類才分得出來）；選項順序同表格。後台商品篩選選到父分類只會看到直接掛在它底下的商品——ADR-041 明定後台 `GET /v1/products` 不加 `includeDescendants`，這是預期行為。
