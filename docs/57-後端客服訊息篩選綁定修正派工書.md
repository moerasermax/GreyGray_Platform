# BE-57 客服訊息列表 status 篩選綁定修正

**給一個子代理。單檔修正＋一支測試，無契約變更、無 migration。** 依 `docs/45`「小包不必走完整條鏈」，不做外部覆驗。

## 0. 事實（Leader 2026-09-24 以 Playwright＋AI 後台帳號實測、讀 log 與原始碼查證）

- 後台「客服訊息」頁預設篩選「未結案」，送出 `GET /v1/support/tickets?limit=20&status=open`，後端回 **400**，畫面顯示「請求內容格式不正確。」——**這一頁一打開就壞**。
- Admin Host log 的逐字錯誤：`BadHttpRequestException: Failed to bind parameter "Nullable<SupportTicketStatus> status" from "open".`
- 凍結契約 `docs/api/openapi.admin.yaml` 的 `SupportTicketStatus` 是 `enum: [open, resolved]`，前端照契約送小寫，**前端沒有錯**。
- `SupportTicketStatus`（`src/Modules/CustomerService/GreyGray.Modules.CustomerService.Contracts/CustomerServiceContracts.cs`，只讀參考、不改）用 `[JsonStringEnumMemberName("open")]` 標註，**這個屬性只作用在 JSON 序列化**；Minimal API 的查詢參數綁定不認它，所以小寫值綁不進 `Open`。
- 為什麼一直綠燈：`GreyGray.CustomerService.Tests` 直接呼叫 `SupportEndpoints.ListTicketsAsync(...)` 並傳入列舉值，**繞過了 ASP.NET Core 的參數綁定**——真正會失敗的那一層從來沒被測到。
- 第四十波已部署，正式站跑的是同一份程式碼。**合理推論**正式站後台客服訊息頁同樣壞著（未登入正式站實測，列為尚待確認）。

## 2. 要求

1. `GET /v1/support/tickets` 的 `status` 查詢參數必須接受契約值 `open`、`resolved`（小寫）；省略時為全部（行為不變）；**契約以外的值**回既有的 400 問題格式（可以是現在的 malformed 處理或明確的驗證錯誤，擇一並在報告說明），不得默默當成全部。做法建議：端點改收 `string? status`，由一個小的解析函式依契約值對應到 `SupportTicketStatus`；不要改 `SupportTicketStatus` 本身、不要改 JSON 行為、不要改 `Shared.Kernel`。
2. 新增測試**必須經過真正的 ASP.NET Core 參數綁定**（例如用測試專案已引用的 TestServer／`WebApplication` 最小主機掛上這支端點送 HTTP 請求）；若測試專案沒有可用的主機套件，**不得安裝新套件**，改為對解析函式做完整單元測試，並在報告明列「HTTP 綁定層仍未被自動化測到」。至少涵蓋：`open`、`resolved`、省略、非法值。先紅後綠：改實作前先讓新測試對現行程式碼失敗一次，報告附輸出。
3. 掃描兩個 Host 其餘 7 處以列舉當查詢參數的端點（`OrderStatus?`、`CampaignStatus?`、`ShipmentStatus?`、`PurchaseItemStatus?` 等），逐一對照契約的 enum 字面值大小寫，**只回報**是否有同型風險，不修改（不在所有權內）。
4. 六條鐵則照守；不改契約、不動其他模組。
