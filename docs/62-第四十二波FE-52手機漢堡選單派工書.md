## Leader 定案（取代計畫書的寫法）

1. **頂部列的漢堡鈕用「規則驅動」**：`TopBarRule` 加 `showMenuButton`（商品詳情、購物車 true；結帳 false），`PageTopBar` 自己依規則畫——**頁面檔一行都不改**（照 `showCartLink` 的既有模式）。`topBar.ts` 檔頭若有「不做全站頂部頁首」之類已過時的說明，一併更新。
2. **`MobileSiteHeader` 的顯示規則**：`shouldShowTabBar(p) && normalizePathname(p) !== '/'`，寫成 `_lib/mobileNav.ts`（新檔）的純函式，**pathname 為 null 時回 false**。**不准併進 `shouldShowTopBar`**（pageShell 第 122 行的語意會翻轉）。
   依規則它出現在 18 條路由，**含 `/payment/result`**（流程終點，顯示無妨）；`/payment/:orderId` 兩種殼都沒有，所以「付款頁不放漢堡」自然成立。
3. **每條路由至多一個漢堡鈕**：`MobileSiteHeader`（分頁列那一側、首頁以外）、`HomeSearchHeader`（首頁）、`PageTopBar`（商品詳情、購物車）；結帳與 `/payment/:orderId` 沒有。
   三處共用同一個 storefront 元件 `MobileNavMenu`（漢堡鈕＋`NavDrawer`＋內容），**各自持有自己的抽屜實例**。
4. **抽屜要自己關的三種時機**：點了抽屜裡的連結；**pathname 改變**（含瀏覽器返回、`router.replace`——`MobileSiteHeader` 常駐在 layout，實例不會因換頁而重建）；**視窗寬度到 `lg` 以上**（portal 不會跟著 `lg:hidden` 消失）。
5. **商品詳情頁頂部列右側會有「購物車＋漢堡」兩顆**：右側包一層 flex 加 `gap`，**不改 `TopBar.tsx`**；標題因左右不對稱會略偏，可以接受，Leader 看截圖。
6. **分類在抽屜「第一次打開」時由 client 端取**；**空清單或失敗時整組不畫**。載入中顯示固定高度的佔位，避免下方分組跳動。
7. **捲動鎖只鎖 `document.documentElement`**（`overflow: hidden`，關閉或卸載時還原**原值**），**不動 `body`**：body 設 overflow 會變成新的捲動容器，sticky 頂部列會失效，關閉時焦點還給漢堡鈕還會把整頁捲回頂端。抽屜內部捲動區加 `overscroll-contain`。
8. **客服面板不用一起處理**：全站只有 NavDrawer 會鎖捲動；抽屜遮罩（z 100）蓋住客服按鈕（z 50），客服面板開著時它的遮罩也蓋住漢堡鈕，兩者不會同時打開。
