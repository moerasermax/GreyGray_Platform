# FE-49 後台依角色隱藏無權限區塊與訂單詳情數字對齊

## 證據與範圍
Leader 2026-09-24 以 Playwright＋本機 Chrome、兩個 AI 專用 dev 後台帳號（Owner、ReadOnly）實測：
1. **唯讀帳號的儀表板**：「負債 vs 現金」與「最近分錄」兩區各顯示一個大的「你沒有執行這項操作的權限。」＋「重試」，因為頁面對 `/v1/ledger/liability-vs-cash`、`/v1/ledger/entries` 發請求、後端回 403（帳務需要 Accountant 以上，側邊欄 `帳務` 的 `requiredRole` 也是 Accountant）。沒權限看的東西不該讓人撞錯誤，「重試」也永遠不會成功。
2. **唯讀帳號的訂單詳情**：頁面呼叫 `/v1/shipments` 回 403（出貨需要 Operator 以上，側邊欄 `出貨` 也是 Operator）。
3. **訂單詳情（所有角色）版面錯位**：訂單編號標題比上方「← 回訂單列表」右縮一截；資訊區的金額與「—」被推到欄位最右，標籤卻在左，看起來像表格壞掉。根因：`.gg-numeric`（`packages/ui/src/tokens/admin.css:198`）從第一波就含 `text-align: right`，本意給表格數字欄，但這頁把它套在標題與「標籤＋數值」區塊。
只修展示與請求時機，不動 API、角色規則本身或後端權限。

## 要求
1. 目前角色從既有 `getSession()` 取得（`(dash)/layout.tsx` 在拿到員工資料前不渲染子頁，所以子頁渲染時它一定有值），用既有 `hasRequiredRole` 判斷，**不要複製一份角色階層**。
2. 儀表板：角色未達 Accountant 時，**不發**兩支帳務請求、不渲染「負債 vs 現金」與「最近分錄」兩區（不顯示錯誤、不顯示「沒有權限」占位）；Accountant 以上行為完全不變。KPI 四格不動。
3. 訂單詳情：角色未達 Operator 時不發 `/v1/shipments`，出貨單區改顯示一行中性說明（例如「出貨單需要營運以上權限才能查看。」），不顯示錯誤樣式；Operator 以上行為不變。其他會發寫入動作的按鈕是否依角色隱藏維持現狀（後端才是權限的最後防線），在報告列出你看到的按鈕與角色對照即可。
4. 訂單詳情的標題（訂單編號）與資訊區「標籤＋數值」改為靠左對齊（保留等寬數字字型），品項表格等表格欄位的數字仍靠右；**不要改 `.gg-numeric` 全域定義**（會影響所有表格），在本頁以既有 utility 覆寫或改用不含右靠的寫法。
5. 深色模式、既有 loading／error／empty 分支保留。
