## 0. 這一波要解的問題：cursor 分頁的 `Where` 子句一樣被 EF Core 翻譯不成 SQL

**背景**：BE-29（第十四波）修好了 `OrderBy`／`ThenBy` 子句裡
`.Id.Value` 拆開強型別 ID 排序、EF Core 值轉換器翻譯不成 SQL 的問題
（`GET /v1/orders`／`GET /v1/shipments` 第一頁 500）。但 BE-29 自己補的
迴歸測試同時證實：**cursor 分頁（帶 `?cursor=` 的「下一頁」請求）用的
`Where` 子句踩的是同一顆地雷**，只是因為第一頁（無 cursor）不會走到這段
程式碼，瀏覽器點開列表頁第一次看不出來，只有真的往後翻頁才會 500。
派工書明文把這個排除在 BE-29 範圍外（見 `docs/26`），只留了一條會說話的
`Skip` 測試記錄現況，沒有動手修——這一波就是把它修掉。

**根因**（跟 BE-29 完全同一類）：`OrderId`／`ShipmentId` 是
`readonly record struct XxxId(Guid Value)` 包出來的強型別 ID，`Where`
子句裡直接寫 `order.Id.Value.CompareTo(cursorOrder.Id.Value) < 0`——
`.Value` 把 EF Core 的值轉換器（value converter）繞過去，變成先在
記憶體裡解開兩個 GUID 再比大小，這種寫法 EF Core 的 LINQ-to-SQL 翻譯器
處理不了，真的执行時會丟例外（對真 Postgres）。

**已經在這個 repo 裡驗證過可行的修法**（`GreyGray.Modules.Ledger.Contracts`
的 `EntryId`）：**不要拆開 `.Value` 比較，改成幫強型別 ID 自己定義
`<`／`>`／`<=`／`>=` 這幾個運算子**，運算子內部才拆 `.Value.CompareTo`，
`Where` 子句裡直接寫 `order.Id < cursorOrder.Id` 這種形狀——EF Core 認得
使用者自訂運算子重載，會正確翻譯成 SQL 的 `<`／`>` 比較。Ledger 的游標
分頁本來就是用這個寫法，這是 repo 裡本來就有的、經過驗證的參考模式，不是
這一波新發明的做法。

**這一波唯二要改的地方**（已經逐行確認過，只有這兩處）：

1. `src/Modules/Ordering/GreyGray.Modules.Ordering.Contracts/OrderingContracts.cs:15-20`——
   `OrderId` 這個 `record struct`，仿照
   `src/Modules/Ledger/GreyGray.Modules.Ledger.Contracts/LedgerContracts.cs:17-30`
   的 `EntryId` 加上同樣四個運算子。
2. `src/Modules/Fulfillment/GreyGray.Modules.Fulfillment.Contracts/FulfillmentContracts.cs:11-16`——
   `ShipmentId` 這個 `record struct`，同樣加上那四個運算子。

**這兩個 `Where` 子句本身也要順手改掉**（不改運算子只是白加，沒有意義）：

3. `src/Modules/Ordering/GreyGray.Modules.Ordering.Infra/OrderingRepository.cs:123`——
   `&& order.Id.Value.CompareTo(cursorOrder.Id.Value) < 0));` 改成
   `&& order.Id < cursorOrder.Id));`。
4. `src/Modules/Fulfillment/GreyGray.Modules.Fulfillment.Infra/FulfillmentRepository.cs:61`——
   `&& shipment.Id.Value.CompareTo(cursorShipment.Id.Value) < 0));` 改成
   `&& shipment.Id < cursorShipment.Id));`。

**這一波不用管**：`OrderBy`／`ThenBy` 那段已經是 BE-29 修好的
`.ThenByDescending(order => order.Id)`（直接排序整個 ID 型別），不用再動；
`Procurement` 模組沒有 cursor 分頁（`docs/10` 的
`GET /v1/campaigns/{campaignId}/purchase-items` 只有 `status` 這個 query
參數，沒有 cursor），不在這一波範圍；`Catalog`／`CatalogServices.cs:388`
也有一處 `.Value.CompareTo`，但那是**商品前台列表**的分頁，不在「現在卡在哪」
#17 描述的「訂單／出貨清單」範圍內，這一波不動它，如果子代理覺得應該
一併修，在自驗報告寫清楚理由但不要自己動手改（不在 allow 清單內）。

public static bool operator <(OrderId left, OrderId right) => left.Value.CompareTo(right.Value) < 0;
