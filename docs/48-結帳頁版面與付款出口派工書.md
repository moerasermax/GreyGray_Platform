## 要求
1. 新增 `CheckoutOrderSummary`（純展示元件）：標題「訂購明細」，列出購物車品項（縮圖用既有 `Thumbnail`、商品名兩行截斷、規格、數量、該列金額）、件數合計、商品小計；詢價完成時再顯示運費與應付總額（沿用現在配送卡裡那三列的資料與 `PriceDisplay`、`ExplainDisclosure`）。資料**只用頁面已經載入的 `cart` 與 `quote`**，不新增 API 呼叫、不自己做金額運算（列金額與小計用 API 回傳欄位或既有 `_lib/subtotalPreview` 之類已驗證的 helper；找不到可用欄位就只列數量與單價，寫進報告）。
2. 版面：`lg` 以上兩欄——左欄是現有表單卡片（配送、地址或門市與收件人、留言，順序不變），右欄 `CheckoutOrderSummary`，右欄 `sticky`（top 讓出 FE-44 的頁首高度 `--gg-top-bar-height` 加間距）。`lg` 以下單欄，明細放在表單卡片**之前**，品項超過 3 列時預設只顯示前 3 列＋「顯示全部 N 件」的原生 `<details>`（不寫 JS accordion）。
3. 金額從配送卡移到明細之後，配送卡只留配送方式與錯誤訊息；**`BottomActionBar` 的應付總額與送出按鈕、disabled 條件、提示文字完全不動**。
4. 以下全部不動：詢價序號與冪等鍵、`quoteActionsRef`、草稿還原、送出訂單流程、`AddressSelect`／`ConvenienceStoreField`／收件人欄位的行為與驗證、`PageTopBar`、空購物車狀態。
5. `/payment/:orderId` 的 `ErrorState` 下方加兩個出口連結：「查看我的訂單」（`/orders`）與「回首頁」（`/`），用既有按鈕／連結樣式。**只在錯誤狀態顯示**；正在導轉綠界的狀態不加任何可點的東西（那是刻意的，見 `TAB_BAR_RULES`）。`TAB_BAR_RULES` 本身不改。
6. 長商品名、大金額（例如 NT$1,234,567）、10 件以上品項在 390 與 1440 都不可水平溢出或擠壓數量／金額欄。
