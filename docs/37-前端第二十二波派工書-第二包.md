## 0. 事實

### 0.1 為什麼要做

FAQ 有三處寫「請聯絡客服」，但**站上沒有任何客服管道**。
使用者 2026-09-19 拍板：右下角做展開式客服小視窗，**引導式選單、不接 AI**，
客人選不到答案就留言，留言進**後台自己的客服工單列表**。

**不接 AI 是明確決定**（ADR-040）：引導式選單不會亂承諾退款，不花 API 費用，也不用把金鑰放正式機。
⚠ **不要自作主張接任何模型或第三方客服套件。**

### 0.3 契約（Leader 已凍結，BE-55 照同一份做）

| 端點 | 身分 | 成功 | 失敗 |
|---|---|---|---|
| `POST /v1/support/tickets` | **匿名可打** | `201 SupportTicket` | `422 support.contact-required`、`429 support.too-many-requests` |
| `GET /v1/support/tickets`（後台） | `ReadOnly` | `200 SupportTicketPage` | — |
| `GET /v1/support/tickets/{id}`（後台） | `ReadOnly` | `200 SupportTicket` | `404` |
| `POST /v1/support/tickets/{id}/resolve`（後台） | `Operator` | `200 SupportTicket` | `404`、`409 support.already-resolved` |

**建立工單的 request**

| 欄位 | 型別 | 必填 |
|---|---|---|
| `message` | `string`，1-2000 字 | ✅ |
| `contactEmail` | `string \| null` | email 與 phone **至少一個** |
| `contactPhone` | `string \| null` | 同上 |
| `menuPath` | `string[]`，最多 5 層、每層 ≤ 100 字 | ❌ |
| `orderId` | `uuid \| null` | ❌ |

**`SupportTicket` 回應**：`id`、`status`（`open` / `resolved`）、`message`、`contactEmail`、`contactPhone`、
`menuPath`、`orderId`、`customerId`、`createdAt`、`resolvedAt`、`resolvedBy`、`staffNote`。

列表是**游標式分頁**：`limit` 預設 20 上限 100、**不回總筆數**、回 `nextCursor`。

⚠ **前台沒有「查詢我的工單」端點**（匿名工單沒有安全的查詢方式）。
這是刻意的，**不要在前台做工單查詢頁**。

## 1. 要做的事

### 1.1 右下角客服小幫手（前台）

**行為**

1. 收合時是一個右下角的小按鈕（不要一進站就自動展開，那很煩）
2. 展開後給幾個常見問題按鈕，**選項與答案直接取自 `FAQ_GROUPS`**
   ——⚠ **不要另外抄一份文案**，抄了就會跟 FAQ 頁走鐘（FE-36 正在改那些文字）
3. 客人選了問題 → 顯示答案 → 再問「這樣有解決嗎？」
4. 選「沒有解決」或「其他問題」→ 進留言表單
5. 留言表單：訊息（必填）＋ email 或手機（至少一個）
   - 已登入時：聯絡方式可預填，但要讓客人改
   - ⚠ **匿名也要能留言**（訪客也會有問題）
6. 送出 → 打 `POST /v1/support/tickets`，`menuPath` 帶上客人走過的選單路徑
7. **送出後要告訴客人「多久會回」**，不要只說「已送出」就結束
8. `429` 要顯示「你剛剛已經留過言了，我們會儘快回覆」這類訊息，不要顯示技術錯誤

**⚠ 版面規則（`walk-the-journey` 教訓）**

- 小幫手在每一頁都看得到，但**不能擋住任何頁面的主要操作**
- **結帳頁的送出鈕、購物車的結帳鈕**尤其要檢查
- **360px 下**展開後不能蓋滿整個畫面到沒有關閉的路；關閉鈕一定要看得見
- 底部有 `StorefrontTabBar` 的頁面，小幫手按鈕不要疊在分頁列上

### 1.2 後台「客服訊息」頁

- `frontend/apps/admin/app/(dash)/tickets/page.tsx`（新檔）
- `NAV_DEFINITIONS` 加一個側邊選單項
- 列表照 `frontend/apps/admin/app/(dash)/orders/page.tsx` 的形狀：游標分頁 ＋「載入更多」
- 至少要能**只看未結案的**
- 列表上一眼要看到：什麼時候來的、客人問什麼（節錄）、怎麼聯絡、處理了沒
- 點進去看完整訊息與 `menuPath`（客人是卡在哪一題才問的）
- 「標記已處理」＋ 備註 → `POST .../resolve`
- ⚠ `409 support.already-resolved`（別人剛處理過）要顯示看得懂的訊息並刷新，不要卡住

### 1.3 API 呼叫放哪

⚠ **不要改 `frontend/packages/api-client/`**——FE-34 正在動那個套件，會撞。
客服端點的型別與呼叫寫在 `frontend/apps/storefront/app/_lib/` 與 `frontend/apps/admin/app/(dash)/tickets/` 自己的檔案裡（新目錄）。
（等這一波收完，Leader 再決定要不要收編進 api-client。）

## 3. 驗證要求

1. `pnpm --filter storefront test`（現況 643）、`pnpm --filter admin test`、`pnpm --filter @greygray/ui test`
2. `typecheck`、`lint`、`build` 全過
3. 測試要涵蓋：
   - 收合／展開、關閉鈕可用
   - 選單走到答案、走到「其他問題」進留言表單
   - email 與手機都沒填 → 擋下（前端先擋，不要等後端 422）
   - `message` 超過 2000 字 → 擋下
   - 送出成功顯示「多久會回」
   - `429` 顯示的是看得懂的訊息
   - `menuPath` 真的有帶出去（不是空陣列）
   - 後台列表游標分頁、只看未結案、重複結案的 `409`
4. ⚠ **360px** 下：展開不蓋死、關閉鈕看得見、不疊在分頁列上
5. ⚠ **結帳頁與購物車頁**：小幫手不擋住送出／結帳鈕（**這兩頁一定要各截一張圖或寫一條測試**）
