## 0. 這一波要做的事：後端契約已經有的欄位／端點，前端補上顯示與操作

**背景**：BE-31（後端第十五波，`docs/27-後端第十五波派工書.md`）實作了 ADR-026——
訂單品項「部分買到」時，買到的數量照常出貨，短缺的數量由營運決定退款去處
後才真的退款。契約已經有：

1. `AdminOrderLine.quantityShortfall`（`docs/api/openapi.admin.yaml` 第 1303-1309 行）：
   `integer`，不在 `required` 清單裡（型別產生器會產生成可選欄位），
   0 或缺省代表沒有短缺。**判斷「還在等退款決定」的條件是
   `(line.quantityShortfall ?? 0) > 0 && line.refundedAmount == null`**——
   這是契約文件本身寫的判斷式，不是這一波自己發明的，直接照抄。
2. `POST /v1/orders/{orderId}/lines/{lineId}/refund-shortfall`
   （`docs/api/openapi.admin.yaml` 第 599-629 行）：
   requestBody 跟既有的 `.../lines/{lineId}/cancel` **一模一樣**
   （`{ reason: string, refundTo: RefundDestination }`），response 也是
   `AdminOrder`。**這代表前端可以直接重用 `CancelAdminOrderRequest` 這個
   既有型別，不用新增型別。**

**這一波不重新設計任何東西**——後端的契約設計、欄位語意、按鈕出現條件，
全部已經在 BE-31 定案（見 `docs/27` 與 `.dispatch/reports/BE-31.md`），
你要做的是照既有的「取消品項」模式（`CancelOrderLineDialog.tsx` ／
`cancelOrderLine`）複製一份對應「退短缺款」的版本，形狀對齊、文案換掉。

## 5. 工作包

### FE-20　訂單品項顯示短缺數量＋新增「退短缺款」操作入口　🔴

**相依**：無　**獨佔**：見 §3

#### 必做 1　跑 `pnpm api:generate`，確認型別跟上契約

```
pnpm api:generate
```

跑完之後確認 `frontend/packages/api-client/src/types.admin.ts` 裡
`AdminOrderLine` 多了 `quantityShortfall`，且新增了
`/v1/orders/{orderId}/lines/{lineId}/refund-shortfall` 這個路徑的型別定義。
這一步只是重新產生檔案，不是手改。

#### 必做 2　`admin.ts` 新增 API 函式

在 `cancelOrderLine`（第 275-283 行）後面，比照它的形狀新增：

```typescript
export function refundOrderLineShortfall(
  client: ApiClient,
  orderId: string,
  lineId: string,
  body: CancelAdminOrderRequest,
  options: MutationOptions,
): Promise<S['AdminOrder']> {
  return client.post(`/v1/orders/${orderId}/lines/${lineId}/refund-shortfall`, { body, ...options });
}
```

函式名你可以自己微調（例如 `refundLineShortfall`），但要跟頁面裡 import 的
名字一致，且要讓看的人一眼看出「退短缺款」跟「取消品項」是兩個不同動作。
`CancelAdminOrderRequest` 直接沿用既有型別（第 61-64 行），不新增介面。

#### 必做 3　新增 `RefundShortfallDialog.tsx`

複製 `CancelOrderLineDialog.tsx`（107 行）整個結構到同目錄新檔
`RefundShortfallDialog.tsx`，改動：

- 元件名 `RefundShortfallDialog`，props 介面 `RefundShortfallDialogProps`
- 額外需要一個 prop 顯示短缺數量（例如 `shortfallQuantity: number`），
  用在 `title`／`description` 裡讓使用者看得到退的是幾件
- `title` 例如 `` `退還短缺款：${lineName}` ``，`description` 說明這是
  「買到的數量已經出貨，短缺的 ${shortfallQuantity} 件現在退款」
  這一類的文字（你自己判斷措辭，但要包含短缺件數，讓操作者確認退的量對不對）
- `Field` 的 `htmlFor`／`id` 前綴改成不會跟取消品項對話框衝突的字串
  （例如 `refund-shortfall-reason`），因為兩個對話框可能同時掛在同一個頁面的
  DOM 上（即使不同時開）
- 按鈕文案改成「確定退款」／「不退款」這一類，不要沿用「取消」字眼
  （這不是取消品項，品項本身還是照常出貨）
- 其餘邏輯（`reason`／`refundTo` state、`RefundDestinationFields` 重用、
  錯誤處理、`submitting` disable、`handleSubmit` 呼叫 `onConfirm` 再
  `reset()`＋`onClose()`）原封不動照抄取消品項對話框的模式

#### 必做 4　`[orderId]/page.tsx` 接線

1. import 新的 API 函式與新對話框元件
2. 新增 state：`const [refundShortfallLine, setRefundShortfallLine] = useState<OrderLine | null>(null);`（放在 `cancelLine` 旁邊，第 52 行附近）
3. 新增 handler（仿 `handleCancelLine`，第 100-107 行）：

   ```typescript
   async function handleRefundShortfall(input: { reason: string; refundTo: S['RefundDestination'] }) {
     if (!refundShortfallLine) return;
     const payload = { orderId, kind: 'refund-shortfall', lineId: refundShortfallLine.id, input };
     const updated = await refundOrderLineShortfall(
       browserApi(),
       orderId,
       refundShortfallLine.id,
       input,
       { idempotencyKey: idempotency.current(payload) },
     );
     idempotency.complete();
     setOrder(updated);
     toast.show('success', `品項「${refundShortfallLine.name}」的短缺款已退款。`);
   }
   ```

   `payload` 的 `kind` 要跟 `handleCancelLine` 的 `'line'` 區分開（例如
   `'refund-shortfall'`），否則同一張訂單裡「取消品項」與「退短缺款」的
   idempotency key 可能撞在一起（`usePayloadIdempotency` 是拿 payload 內容
   算 key，`kind` 不同才能保證不同操作絕對不會共用同一把 key）
4. `lineColumns` 的 `refundedAmount` 欄（第 166-171 行）：在現有的
   `MoneyCell` 顯示旁邊，加上短缺數量的次要文字（`(line.quantityShortfall ?? 0) > 0` 時才顯示，例如「短缺 2 件」），沒有短缺就不要多顯示任何東西
5. `action` 欄（第 172-190 行）：在既有的「已處理文字 ／ 取消按鈕」判斷式
   之外，額外判斷 `(line.quantityShortfall ?? 0) > 0 && line.refundedAmount == null`
   時多渲染一個「退短缺款」按鈕，`onClick` 設定 `setRefundShortfallLine(line)`。
   這個按鈕要能跟取消品項按鈕同時出現（兩者互不排斥），版面你自己決定
   （例如兩個按鈕上下排或用 `flex gap` 並排）
6. 頁面底部（第 337-342 行 `<CancelOrderLineDialog>` 旁邊）新增
   `<RefundShortfallDialog>` 實例，`open={refundShortfallLine !== null}`，
   `onClose={() => setRefundShortfallLine(null)}`，`onConfirm={handleRefundShortfall}`，
   `shortfallQuantity` 傳 `refundShortfallLine?.quantityShortfall ?? 0`

   現成的短缺訂單資料，如果沒有真實資料可用，**用元件層級或截圖層級的驗證
   替代**——例如暫時在瀏覽器 devtools 或本地測試腳本塞一筆
