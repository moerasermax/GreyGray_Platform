## 0. 這一波要解的問題：機密與連線設定，開發環境跟正式機都沒有投遞機制

FE-12（第九波）對真後端實測時發現：開發環境缺 `Identity:DataProtectionKey` 與
`Payment:ECPay:MerchantId` 這兩個必要設定，登入、註冊、購物車全部 500。
往上追查發現問題比 FE-12 回報的更根本：

**`ops/deploy.ps1` 現在對「正式機」完全沒有投遞任何 `ConnectionStrings:*` 或應用層機密的機制。**
不只是綠界那五個值——**全部 13 個模組的資料庫連線字串，正式機一個都沒有投遞管道。**
`ops/deploy.ps1:213-219` 的 `AppEnvironmentExtra` 只設了 `DOTNET_ENVIRONMENT`／
`ASPNETCORE_ENVIRONMENT`／`ASPNETCORE_URLS` 三個跟業務設定完全無關的鍵。這代表就算
`ops/deploy.ps1` 今天被拿去對正式機跑一次，三個 Host 開機後**連資料庫都連不上**——
這正是 E1（正式機部署）至今沒有完成過一次成功部署的根本原因之一。

**這一波要做的：把開發環境已經在用、已經驗證過的機密模式，延伸到正式機。**
不是發明新機制——`ops/install-dev-environment.ps1` 已經有一套可行的做法：
`$InstallRoot\secrets\` 目錄、ACL 收緊到目前使用者、明文檔案（`Protect-SecretDirectory`
／`New-RandomPassword`，見 §1）。這一波把同一套模式套進 `ops/deploy.ps1`，
外加開發環境自己缺的 `Identity:DataProtectionKey`。

**這一波刻意不做的**：綠界（ECPay）**正式**商店代號與金鑰本身（E3，老闆要去辦，
不是機械可派的工）；綠界**開發**測試特店代號也一樣——目前沒有現成的測試憑證，
**不要自己編一組值填進去**。這一波只把 `Payment:ECPay:*` 的投遞管道蓋好、
接口留著，值留空，跟 E3 用同一套等待方式。做完之後 `Identity:DataProtectionKey`
那半才是真的解除，購物車／付款那半仍然要等真的綠界憑證出現。

#### 必做 1　新增 `ops/lib/Secrets.ps1`

```powershell
function New-DataProtectionKey {
    # 32 bytes、Base64 編碼，不做任何字元替換——
    # IdentityDataProtector 要求 Convert.FromBase64String 解碼後正好 32 bytes（AES-256）。
    # 不要沿用 New-RandomPassword：它會把 +/= 換成 x，解碼結果會跟預期不同。
    $bytes = [byte[]]::new(32)
    [System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
    return [Convert]::ToBase64String($bytes)
}

function Protect-SecretDirectory {
    # 跟 ops/install-dev-environment.ps1:74-83 逐字相同的邏輯——這裡是給
    # ops/deploy.ps1 用的獨立副本（deploy.ps1 不 dot-source install-dev-environment.ps1），
    # 兩邊各自維護是刻意的：dev 腳本已經在用、驗證過，不要去動它去共用這支。
    param([Parameter(Mandatory)][string]$Path)
    $acl = Get-Acl -LiteralPath $Path
    $acl.SetAccessRuleProtection($true, $false)
    foreach ($identity in @([Security.Principal.WindowsIdentity]::GetCurrent().Name, 'BUILTIN\Administrators', 'NT AUTHORITY\SYSTEM')) {
        $rule = New-Object Security.AccessControl.FileSystemAccessRule($identity, 'FullControl', 'ContainerInherit,ObjectInherit', 'None', 'Allow')
        $acl.AddAccessRule($rule)
    }
    Set-Acl -LiteralPath $Path -AclObject $acl
}

function New-SecretPassword {
    # 跟 ops/install-dev-environment.ps1:54-59 的 New-RandomPassword 邏輯相同，
    # 這裡取一個不同的名字避免跟 dev 腳本裡「同名不同檔」的函式混淆。
    param([int]$Length = 32)
    $bytes = [byte[]]::new($Length)
    [System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
    return ([Convert]::ToBase64String($bytes) -replace '[+/=]', 'x')
}
```

（以上是形狀示意，不是要你逐字照抄貼上——變數命名、要不要用 `param()` 型別驗證，
你自己判斷；但 `New-DataProtectionKey` **不做任何字元替換**這件事不能變。）
