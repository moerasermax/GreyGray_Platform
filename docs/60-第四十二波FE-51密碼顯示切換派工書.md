## 要求

### 1. 前台 `PasswordInput`（`frontend/packages/ui/src/components/PasswordInput.tsx`，新檔）

- 檔頭 `'use client'`（有 state）。
- props：沿用前台 `InputProps`，但 **`type` 由元件自己管、不開放**；**`id` 必填**（切換鈕的 `aria-controls` 要指向它）；`autoComplete` 必填，只能是 `'current-password'` 或 `'new-password'`。
  `invalid` 等其他 props **留在 rest 裡展開轉傳**（`exactOptionalPropertyTypes`，見上）。
- **結構照這樣做**：外層一個 `relative` 容器；裡面沿用前台 `<Input>`，className 加 `pr-[var(--gg-touch-min)]`（右邊留出按鈕的位置）與 `[&::-ms-reveal]:hidden`；
  切換鈕 `absolute inset-y-0 right-0`（絕對定位後 `self-start` 就不影響版面）。**聚焦樣式用 `Input` 自己的**，外層不要再畫框線。**尺寸、顏色只從 token 取**（前端四條）。
- 切換鈕用 `IconButton`：
  - `type="button"`（不能送出表單）
  - 隱藏時圖示是「眼睛」、`aria-label="顯示密碼"`；顯示時圖示是「眼睛加斜線」、`aria-label="隱藏密碼"`
  - **不加 `aria-pressed`**（`aria-label` 切換與 `aria-pressed` 兩種寫法不混用）
  - `aria-controls` = 輸入框的 `id`
  - 觸控範圍 ≥ 44×44（全域 CSS 已保證 `button` 的下限，不要用別的樣式把它壓小）
- 行為：
  - **始終是同一個 `<input>`**，切換只改 `type`；不准用條件式畫兩個 input（會重新掛載、丟掉輸入法狀態與瀏覽器的密碼管理）。
  - `autoComplete` 在兩種狀態下都不變。
  - **按切換鈕時的順序**：先記下 `selectionStart`／`selectionEnd` → **直接把 DOM 的 `input.type` 改掉** → 還原選取範圍並把焦點送回輸入框 → 最後才 `setState`。
    ⚠ **不准在 `setState` 之後的同一個 handler 裡還原**——那時 React 還沒把新的 `type` 寫進 DOM，還原會作用在舊狀態上，純函式測試全綠、瀏覽器裡卻壞掉。
  - **表單送出前自動切回隱藏**：在 effect 裡對 `input.form` 掛 `submit` 監聽（capture），直接把 DOM 的 `type` 設回 `password` 並更新 state。沒有外層 form 時什麼都不做。卸載時移除監聽。
- **可測的純函式**（從同一個檔匯出，給測試用；**名稱一律帶 `password` 前綴**，例如 `passwordToggleState`，避免在 barrel 撞名）：
  - 由「是否顯示」算出 `{ inputType, toggleLabel }`
  - 「切換」：吃一個只有 `type`／`selectionStart`／`selectionEnd`／`setSelectionRange`／`focus` 的最小介面，照上面的順序做完 DOM 那一半
  - 「送出時切回隱藏」的處理函式：吃一個只有 `type` 的最小介面
- 使用者看得到的字串（「顯示密碼」「隱藏密碼」）**寫成檔案頂端的模組常數**，不要散在 JSX 裡（為第四十六波抽字串鋪路）。
- 圖示：在 `frontend/packages/ui/src/components/icons/index.tsx` 加 `IconEye`、`IconEyeOff`，照 `BaseIcon` 的寫法。
- 在 `frontend/packages/ui/src/index.ts` 匯出。
