### 0.1 使用者 2026-09-02 撞到的（#37）與拍板（ADR-030）

使用者親自走旅程，購物車只放預購商品，按「送出訂單」得到「系統發生問題，請稍後再試」——而且是還沒登入的狀態。

說明文字寫「混合訂單必須指定 `shippingPolicy`」，schema 卻一律必填；前端照說明文字做（只有混合才問、否則送 `null`），
用 `!` 把型別檢查蓋掉，`null` 就溜出去、在後端綁定期炸掉。使用者拍板「用第二種方式修」→ ADR-030（`docs/00-decisions.md`，

單一模式忽略客人的值、依 line 組成推導；混合沒帶回 `422 checkout.shipping-policy-required`；壞掉的 body 回 400 problem+json。

**前端現在送 `null` 的行為變成對的了**——這一包要做的是讓型別跟上，把 `!` 拿掉。

## 1. 必做

### 必做 A　重生型別，拿掉 `!`

1. `pnpm api:generate`。預期：`packages/api-client/src/types.storefront.ts` 的 checkout request body 裡 `shippingPolicy` 變成可 `null`／可省略；
   `types.admin.ts` **零 diff**（把 `git diff --stat packages/api-client/` 貼進報告）。
2. `checkout/page.tsx` 第 152 行 `shippingPolicy: shippingPolicy!` → `shippingPolicy`（型別現在允許 `null`）。`cartRules.ts` 不動。
3. 全 repo grep `shippingPolicy!`：零命中。`pnpm --recursive typecheck` EXIT=0。
4. 若 codegen 產生的型別是 `shippingPolicy?: ShippingPolicy | null`，`CheckoutInput` 的既有測試（`idempotentAction.test.ts` 等）照舊；不要為了型別去改契約檔。

### 必做 B　#36 前端側：登出後徽章歸零

`me/page.tsx` `handleLogout`：`storefrontApi.logout` 成功之後、`router.replace('/')` 之前，呼叫 `publishCart(null)`。
失敗分支不動（失敗時 cookie 還在，徽章維持原值是誠實的）。測試：登出成功 → `getCartItemCount()` 為 0（或 `null`，照 `cartBadge.ts` 的語意）；登出失敗 → 不變。

### 必做 C　FE-25 ⑦：登入／註冊頁帶 `?next=` 時，亮 `next` 所屬的分頁

`tabs.ts` 的 `activeTabHref`（第 154 行附近）：路徑是 `/login` 或 `/register` 且帶 `next` 參數時，先用 `safeNext(next)`（`app/_lib/auth.ts`，FE-25 寫的，只收站內路徑）
算出目的地，再用**同一套規則**決定亮哪個分頁；沒帶 `next`、或 `next` 不屬於任何分頁時維持亮「我的」。
`tabs.test.ts` 加：`/login?next=%2Fcheckout` 亮購物車、`/login?next=%2Fcampaigns` 亮開團、`/login` 亮我的、`/login?next=//evil` 亮我的。
既有斷言一條都不刪（總條數只增不減）。

### 必做 D　結帳頁被帶去登入再回來時，保留已填的內容

- 範圍：`deliveryMethod`、`shippingPolicy`、`shippingAddressId`、`convenienceStoreCode`、`buyerNote`。
- 做法：401 導向登入**之前**把這五個值存進 `sessionStorage`（鍵含 cart id，例如 `gg:checkout-draft:<cartId>`）；結帳頁載入且購物車 id 相同時還原；
  **送出成功後刪掉**；購物車 id 不同（換了一張車）就不還原並刪掉。用 `sessionStorage` 不用 `localStorage`：分頁關掉就消失，不會跨天冒出來。
- 還原後要重新詢價（`deliveryMethod` 決定運費），沿用頁面既有的詢價流程，不要自己另外算。
- 純函式抽出來（序列化／反序列化／要不要還原的判斷）放 `(checkout)/_lib/`，測試釘住：存→取回一致、cart id 不同不還原、送出成功後清掉、壞掉的 JSON 當作沒有。
- `sessionStorage` 取用一律 try/catch（隱私模式會丟例外），拿不到就當作沒有草稿，頁面照常。
