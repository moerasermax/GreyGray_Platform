## 要修的東西（行號以前端 HEAD `a989806` 為準）

### A. 密碼欄顯示時會被自動大寫／自動修正（中，已確認）

- `frontend/packages/ui/src/components/PasswordInput.tsx:103`～110、`frontend/packages/ui/src/admin/PasswordInput.tsx:101`～108 只切 `type`；切成 `text` 之後，iPhone Safari 會把句首字母自動大寫、做自動修正與拼字檢查——
  客人在註冊頁「顯示密碼」打 `greygray01`，實際存成 `Greygray01`，下次隱藏狀態輸入就登不進去。
- **修法**：兩個 `PasswordInput` 的 input 固定加 `spellCheck={false}`、`autoCapitalize="none"`、`autoCorrect="off"`，**放在 `{...rest}` 之後**（呼叫端不能覆寫）。
- 順手：input 是 `disabled` 或 `readOnly` 時，切換鈕也 `disabled`（前台 `frontend/packages/ui/src/components/PasswordInput.tsx:110` 起、後台同理）。

### B. 抽屜的「商品分類」組非同步出現／消失，下方連結會跳動（中，已確認）

- `frontend/apps/storefront/app/_components/DrawerCategories.tsx:46`、65：失敗或空清單時整組 `return null`；載入中的佔位只有 64px，成功時清單是 N×44px。「商品分類」排第一，下方兩組一定位移（實算 126～200px）。
- **修法**（介面 `DrawerCategories({ open, onNavigate })` **不准改**，FE-55 會接著改這個檔）：
  - **元件一掛載就開始取分類**（不等抽屜打開），結果用**模組層級的快取**（同一次頁面載入內所有實例共用同一個請求）；抽屜打開時多半已經有結果，不會再出現佔位。
  - 失敗時清掉快取；**下次抽屜打開（`open` 變 true）再試一次**。
  - 空清單或失敗時整組不畫（行為不變）；仍在載入時才顯示佔位。

### C. 導覽抽屜的其他小修（低，一併修）

- `frontend/apps/storefront/app/_components/MobileNavMenu.tsx:26` 寫死 `(min-width: 1024px)`：改成 `(min-width: 64rem)`（與 Tailwind v4 的 `lg` 相同），寫成 `_lib/mobileNav.ts` 的常數並註明理由。
  `MediaQueryList.addEventListener` 不存在時（舊版 Safari）退回 `addListener`／`removeListener`——這支在根 layout 的元件裡，丟錯整站會掛。
- `frontend/apps/storefront/app/_components/MobileSiteHeader.tsx:23` 的品牌連結只有約 35px 高：補 `inline-flex items-center min-h-[var(--gg-touch-min)]`。

### D. 付款確認頁（低，一併修）

- **混合訂單句出現兩次**：`frontend/apps/storefront/app/(checkout)/payment/result/page.tsx:208`～210（結果卡）與 `OrderSummary` confirmation 的配送卡（`frontend/apps/storefront/app/(account)/orders/_components/OrderSummary.tsx:129`～131）。**只留配送卡那一處**，拿掉結果卡的。
- **自取訂單的說法不對**：`frontend/apps/storefront/app/(checkout)/_lib/paymentResultSummary.ts` 的兩句一律寫「寄出」。`deliveryMethod === 'SelfPickup'` 時改用：
  - `ShipSeparately`：「這筆訂單有現貨也有預購：現貨可以先取貨，預購商品到貨後另外通知取貨。」
  - `HoldUntilComplete`：「這筆訂單有現貨也有預購：會等預購商品到齊後一起通知取貨。」
  （先確認契約 `DeliveryMethod` 的自取值確實叫 `SelfPickup`；不是的話用實際值並寫進報告。）
- **長品名會溢出**：`OrderSummary` confirmation 品項的名稱與規格補 `break-words`（`CheckoutOrderSummary.tsx` 的 `SummaryLine` 有）。
- **複製的播報**：`frontend/apps/storefront/app/(checkout)/payment/result/page.tsx:199` 的 `aria-live` 掛在按鈕自己身上。改成按鈕旁一個獨立的狀態元素帶 `aria-live="polite"`（放「已複製」／「複製失敗，請手動選取」），按鈕的可存取名稱改成「複製訂單編號」。

### E. 測試本身的 bug（低）

- `frontend/apps/storefront/app/(checkout)/_lib/__tests__/paymentResultSummary.test.ts:42`：原本 `TZ` 是 undefined 時，`process.env.TZ = originalTimezone` 會寫成字串 `"undefined"`。改成原值是 undefined 就 `delete process.env.TZ`。
