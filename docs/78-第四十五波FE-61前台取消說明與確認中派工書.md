## 1. 要做的事

1. **純函式規則**（擴充 `paymentInstructions.ts`）：參數的 `Pick` 可以加**選填** `paymentOverdue`；回傳 union 可以加新值（`'show-overdue'`）；新的布林欄位**只在逾期時出現**（型別宣告為 `showOverdue?: true`），**非逾期時回傳物件的鍵集合必須和現在一模一樣**（既有 `toEqual` 測試不改仍綠）。`undefined` 視為 `false`。判斷順序：**逾期優先**，其次已取號。
   - `orderPaymentPresentation`：逾期 → `canPay: false`、`showCountdown: false`、`showOverdue: true`。
   - `paymentRedirectAction`、`paymentConflictRefreshAction`：逾期 → `'show-overdue'`（不發動付款）；第 144 行既有斷言保留。
   - `paymentInitiationFailureAction`、`shouldReloadOrderAfterPaymentError`：`422 ordering.payment-overdue` 與 `409 payment.instructions-already-issued` 都走「重讀訂單」。
   - `paymentResultPresentation`／`shouldPollPaymentResult`：逾期 → 停止輪詢；回 `title`＝§1.2 的標題、`showConfirmingMessage`／`showUnconfirmedMessage`／`showRetryPayment`／`showManualRefresh`／`showPrice` 全部 `false`、`showOverdue: true`。
2. **確認中區塊**（使用者拍板的文案，一字不差）：標題「繳費期限已過，正在確認付款」；內文「如果你已經繳費，系統收到通知後會自動更新；未繳費的訂單將自動取消。」做成只吃 props 的元件，三個頁面共用。
3. **取消說明**（新純函式＋只吃 props 的元件，三處共用：訂單詳情、付款結果、付款發動）。「已付款」＝`paidAmount != null && paidAmount.amountMinor > 0`。組合規則：
   - 主句：`PaymentExpired` 未付款「這筆訂單因逾期未付款，已由系統自動取消。」、`PaymentExpired` 已付款「這筆訂單已由系統自動取消。」、`Staff`「這筆訂單已由客服取消。」、`Customer`「你已取消這筆訂單。」、`null`／未知值「這筆訂單已取消。」
   - 已付款時接「已付款項會由我們辦理退款。」——**不寫退款方式或時程**（信用卡原路退刷、ATM／超商人工匯款，前台分不出來）。
   - `Staff` 或已付款時最後接一次「如有疑問請聯絡客服。」（只出現一次）。
   - `cancelledAt` 有值時另一行「取消時間：yyyy/MM/dd HH:mm（台灣時間）」。
   - **不准顯示後端任何取消原因文字。**
4. **訂單詳情頁**：已取消 → 標題下方顯示取消說明；逾期 → 顯示確認中、不顯示倒數與「前往付款」；「取消訂單」照舊。
   - **倒數重讀迴圈**：`onExpire` 改成**背景重讀**（不切 Skeleton），而且同一張訂單同一個期限只重讀一次；重讀後仍未逾期也未取消時，倒數位置改顯示固定句「付款期限已到，系統處理中」，不再重讀（頁面 state 擋住，**不改倒數元件**）。
   - 把第 84～89 行的「重讀」邏輯**搬回 `handlePay`**：收到 `409 payment.instructions-already-issued` 或 `422 ordering.payment-overdue` → complete 付款冪等鍵、`setPaying(false)`、重讀訂單；`handleCancel` 收到 `409 ordering.concurrent-update` → 重讀訂單（顯示最新狀態，不只顯示錯誤字）。
   - 逾期時的取消確認對話框多一句「如果你已經繳費，取消後款項會由我們辦理退款。」（未逾期照舊）。
5. **付款發動頁**：第 87 行讀單後與第 67 行重讀後兩處，`'show-overdue'` → 設定訂單並顯示確認中＋「查看訂單明細」「回首頁」兩個出口（樣式照取號卡的出口）；在第 105 行取號分支之前、第 125 行 error 分支之前新增逾期的渲染分支。
6. **付款結果頁**：逾期分支像取號分支一樣提早處理（停止輪詢、顯示確認中，出口沿用「查看我的訂單」）；第 129 行設 `pollExhausted` 時排除逾期；**已取消分支改用 §1.3 的取消說明**（拿掉「依原路退還」）；守住 §0.4 那條原始碼守衛的三項要求。
7. **mock**：
   - `OrderSeed` 擴充選填 `paymentOverdue`、`cancellationSource`、`cancelledAt`、`paid`（讓已取消的種子也能有 `paidAmount`），`buildOrder` 帶出。陣列**最後**加四筆：① 待付款＋逾期（`paymentDueAt` 為過去時間、`paymentInstructions: null`）；② 已取消＋`PaymentExpired`（未付款）；③ 已取消＋`Staff`＋已付款；④ 已取消＋`Customer`。
