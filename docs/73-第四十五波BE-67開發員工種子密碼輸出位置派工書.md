## 1. 要做的事

1. `param` 區最後加 `[string]$CredentialsDir`（預設空字串）。`[string]::IsNullOrWhiteSpace($CredentialsDir)` 時，傳給工具的 `--secrets-dir` **必須和現在完全一樣**（`$secretsDir`）。
2. 給了 `-CredentialsDir` 時，**執行順序固定**：① repo 檢查 → ② 讀 secrets（照舊）→ ③ 建目錄並收緊 ACL → ④ 設環境變數 → ⑤ `dotnet run`。
   - **① 路徑解析與 repo 檢查**：用 `$ExecutionContext.SessionState.Path.GetUnresolvedProviderPathFromPSPath($CredentialsDir)` 轉成絕對路徑（**不准用 `Resolve-Path`**——目錄還不存在時它會丟例外；也不要直接用 `[IO.Path]::GetFullPath` 處理相對路徑——它看的是行程的 cwd，不是 `$PWD`），再用 `[IO.Path]::GetFullPath` 正規化並去掉結尾的分隔符。接著從這個路徑**往上逐層檢查每一個已存在的祖先目錄**：只要有一層含 `.git`（檔案或目錄都算）就 `throw`，訊息寫明「密碼檔不能放在 git repo 裡」——這樣兩棵 worktree 都涵蓋。比對一律 `OrdinalIgnoreCase`。這一步要在讀 secrets 之前、**不准建立任何目錄**。
   - **③ 建目錄＋ACL**：目錄**不存在**才由腳本建立，並對這個**新建的**目錄呼叫 `Protect-SecretDirectory`；目錄已存在就不動它的 ACL（避免斷開既有目錄的繼承）。
   - 把這個路徑傳給 `--secrets-dir`。模組密碼與個資金鑰**仍然**從 `$InstallRoot\secrets` 讀。
3. 腳本開頭的說明註解補一段：參數用途、只影響新建立的帳號（已存在的 email 不會再輸出密碼）、建議用一個還不存在的子目錄讓腳本建立並收緊權限、加了這個參數後縮寫 `-c` 會在 `Configuration` 與 `CredentialsDir` 之間有歧義（請寫全名 `-Configuration`）。
4. 維持 UTF-8 **無 BOM**、維持 LF。
