## 0. 事實（Leader 查證過，逐行）

### 0.1 為什麼要做

2026-09-03 使用者在正式機後台建了商品，SKU 區只有空狀態「契約目前只有 PATCH /v1/skus/{skuId}…SKU 要等後端補上端點才能建立」
（`apps/admin/app/(dash)/catalog/products/[productId]/page.tsx` 第 150-158 行）。沒有 SKU 就沒有價格、庫存、加入購物車；而且就算有 SKU，後台也沒有任何進貨頁，庫存進不來（M2 的 `POST /v1/lots` 只有 API）。
後端 BE-44 已補 `POST /v1/products/{productId}/skus`（ADR-032）；這一包把兩個 UI 缺口補上。

### 0.2 前端現況

- 商品頁 `apps/admin/app/(dash)/catalog/products/[productId]/page.tsx`：第 146-159 行 SKU `DataTable`（欄位 SKU／重量尺寸／可用量／現貨標價／狀態），有寫入權時點列開 `SkuEditDrawer`（第 161-166 行；`_components/SkuEditDrawer.tsx`，走 `updateSku` PATCH）。
- `packages/api-client/src/endpoints/admin.ts` 第 145-152 行 `updateSku(client, skuId, body: S['AdminSkuInput'], options)`；第 120-126 行 `createProduct` 是 POST 的寫法。**沒有 `createSku`、`createLot`、`listLots`。**
  `packages/api-client/src/endpoints/README.md` 第 51-54 行是 operation ↔ 函式對照表。
- 契約（新）：`POST /v1/products/{productId}/skus`（Operator、`Idempotency-Key`、body `AdminSkuInput`、201 `AdminSku`、403／404／422）；
  契約（舊）：`GET /v1/lots?skuId=&cursor=&limit=`（ReadOnly，回 `{ items: Lot[], nextCursor }`）、`POST /v1/lots`（Operator、`Idempotency-Key`、body `{ skuId, quantity ≥ 1, unitCost: Money, batchCode?: string|null }`、201 `Lot`）——都在 `docs/api/openapi.admin.yaml`（`/v1/lots` 第 863-908 行附近）。
- 型別一律從 `pnpm api:generate` 重生的 `types.admin.ts` 拿（`S['AdminSkuInput']`、`S['Lot']`…）；**不准手寫請求型別**（FE-26 已把手寫複本記成追蹤項，不要再加一份）。
- 金額：`Money = { amountMinor, currency }`，`NT$180 = 18000`。表單輸入 NT$ 整數 → `amountMinor` 的轉換照 `SkuEditDrawer` 現貨標價欄位既有的做法（同一個 helper），不要另寫一套。
- 冪等：所有寫入走 `MutationOptions`（既有 `createProduct`／`updateSku` 的呼叫端怎麼給 `Idempotency-Key`，照抄）。

## 1. 必做

### 必做 A　api-client

1. `pnpm api:generate` 重生 `types.admin.ts`（diff 應只多新 operation 相關的型別）。
2. `endpoints/admin.ts` 加 `createSku(client, productId, body: S['AdminSkuInput'], options: MutationOptions): Promise<S['AdminSku']>`（`client.post(\`/v1/products/${productId}/skus\`, …)`）、
   `listLots(client, query: { skuId?, cursor?, limit? }, options)`、`createLot(client, body, options): Promise<S['Lot']>`（body 型別從 `paths['/v1/lots']['post']` 推導，**不手寫**）。README 表加三列。
3. mock（msw）handlers 補這三條，smoke test 各一條（建 SKU 後 `getProduct` 看得到；`createLot` 後 `listLots` 看得到）。

### 必做 B　商品頁「新增 SKU」

- SKU 區標題列右側加「新增 SKU」按鈕（只在 `canWrite` 時），開 `SkuEditDrawer` 的**新增模式**（空表單、`isActive` 預設 true、`mode` 是 Stock 才顯示現貨標價欄；送 `createSku`），成功後 `setReloadKey` 重載、toast「已建立」。
- 空狀態文案改成「還沒有 SKU——點右上角『新增 SKU』」；沒有寫入權時維持只讀文案。
- 422 的 problem details 照既有 drawer 的錯誤呈現（欄位錯誤要看得出是哪一欄）。

### 必做 C　SKU 列「進貨」＋ 批號列表

- SKU 列加操作「進貨」（`canWrite`），開新的 `LotDrawer`（`_components/LotDrawer.tsx`）：上半部列該 SKU 的批號（`listLots({ skuId })`：數量／可用／單位成本／批號／進貨時間），下半部表單：數量（整數 ≥ 1）、單位成本（NT$ 整數 → Money）、批號（選填）→ `createLot`；成功後列表與商品頁一起重載（SKU 的「可用量」要變）。
- 只做 M2 契約有的：不做退貨、不做調整、不做刪除。

### 必做 D　測試與建置

- 既有測試 pattern（page tests＋api-client smoke）各補：新增 SKU 流程、進貨流程、無寫入權不顯示按鈕。
- `pnpm --recursive typecheck`、`pnpm --recursive test`（基準 410 ＋ 新增）、**build 由 Leader 停 dev server 後跑**（不要自己停任何行程）。
