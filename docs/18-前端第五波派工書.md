## 5. 工作包

### FE-12　關掉 mock，對真後端跑一遍　🔴 **這一波的重點**

**相依**：無——**環境已就緒**　**獨佔**：`apps/*/.env.local`

**這一包從第三波等到現在，等的就是後端環境。現在通了。**

**這一包不是寫功能，是驗證。預期產出多半是「發現了什麼」而不是新程式碼。**
如果你交出一堆新程式碼，多半代表你在修不該你修的東西。

**開工前提**（任一成立即可）

- 本機起得了 `GreyGray.Api.Storefront`、`GreyGray.Api.Admin`、`GreyGray.Worker`
  加 PostgreSQL 17 與 Garnet；或
- 連得到 YC（`192.168.0.92`），`ops/verify-environment.ps1` 大部分 PASS

**必做**

1. 兩個 app 的 `.env.local` 把 `NEXT_PUBLIC_USE_MOCK` 設成 `0`，
   `API_INTERNAL_BASE_URL` 指向真的 BFF。
2. **後台登入走一遍真的**：四個角色各登入一次，確認 `gg_admin_session` cookie 真的下來、
   `GET /v1/me` 回的角色正確、`middleware.ts` 擋得住未登入、登出後回不去。
   **這一條就是 M1a-6 驗收第 5 條的補驗**——M1a 的驗收缺的就是它。
3. **前台走一條完整的**：逛 → 加入購物車 → 結帳 → 付款（綠界測試憑證）→ 看訂單。
4. **後台走一條完整的**：看訂單詳情、看分錄、看每團毛利、開一次採購清單、
   **看出貨單列表**（第四波新做的）。
5. 把每一頁的實際結果記下來：哪些頁對真後端是好的、哪些壞了、壞在哪。

**做法要點**

- **不要修後端。** 發現後端的問題就記下來回報，那是後端的事。
- **不要為了讓畫面好看而在前端補資料。** mock 有而真後端沒有的欄位，
  正是這一包要找出來的東西——補上去等於把問題藏起來。
- 契約不符（型別對不上、欄位缺）→ 記清楚是哪個端點、哪個欄位、哪一頁要用，
  **不要自己改契約**。
- SSR 與 client 兩側都要試。第二波踩過的坑是「client 端第一次取資料跑在 msw 接手之前」，
  關掉 mock 之後那條路徑的行為會不一樣。
- **已知會踩到的兩件**（先有心理準備，不要當成自己做錯）：
  - 已付款訂單的取消退款**現在必定失敗**（ADR-024，綠界退款 API 還沒做）
  - 訂單簽收後**不會**變成 `Completed`（ADR-025，鑑賞期 Timer 還沒做）
  這兩個是已知缺口，遇到就記下來，**不是你要修的**。

**自驗（逐條貼出實際指令與實際輸出）**

### FE-16　老闆拍板的四件前端跟進

**相依**：後兩件等 BE-19　**獨佔**：見 §3

#### ① 金額顯示統一 `NT$`（ADR-028）—— 現在就能做

`formatMoney()` 對台幣目前輸出 `$780`，契約的 `unitPriceLabel` 範例是 `NT$780／32 顆`，
同一張商品卡上兩種寫法並存。

**`$` 本來是正確的 ICU 行為不是 bug**（`zh-TW` 是台幣的本地語系），
但老闆決定統一成 `NT$`。

- **只改 `packages/api-client/src/money.ts` 一處**——那個檔的註解早就寫了
  「若之後決定台幣也要顯示成 `NT$`，改這裡一處即可，**不要在呼叫端自己加前綴**」
- 外幣維持 ICU 的既有行為（`US$`、`HK$`），不要一起動
- 改完**跑全部測試**看哪些斷言紅了。你所有權內的自己修；
  **別包的測試檔列清單回報，不要自己改**

#### ② 後台首頁 KPI 拿掉假數字 —— 現在就能做

四塊 KPI 現在是 `dashboardMock.ts` 裡寫死的值。契約沒有彙總端點，
而**營運會相信後台上的數字**——佔位值放在正式環境比沒有更危險。

- 把那四塊拿掉，或改成明確的「尚未提供」狀態（不要顯示任何數字）
- **不要自己發明彙總端點，也不要用列表 API 在前端加總**——
  列表有分頁，加出來的是「這一頁的合計」不是真的合計，而且違反鐵則 2
- `dashboardMock.ts` 裡其他還在用的東西不要一起刪，先確認沒有別處引用

#### ③ 開團表單加漲價詢問逾時欄位（ADR-027）—— ⏸ 等 BE-19

後端 BE-19 會在 `AdminCampaignInput` 加這個欄位。契約落地、`pnpm api:generate`
重跑之後才有型別。

- 開團表單（`campaigns/new/page.tsx`）加一個輸入
- **沒填要有預設值 2 小時**，而且畫面要說明「不填就是 2 小時」
- 文案要讓營運看得懂這個數字的後果：**逾時就自動視為照買，花的是客人的錢**

#### ④ 出貨詳情改打新端點 —— ⏸ 等 BE-19

BE-19 會新增 `GET /v1/shipments/{id}`。現在 `shipments/_lib/api.ts` 是撈
`limit:100` 的列表再在前端過濾——**出貨單超過 100 張之後點詳情會白頁，而且不會報錯**。

契約落地後改成直接打單筆端點。

**自驗（逐條貼出實際指令與實際輸出）**

1. `pnpm typecheck` ／ `test` ／ `build` 四個專案全綠
2. `git diff --name-only` —— 只有你擁有的路徑
3. **`NT$` 改完之後全測試的結果**，以及「哪些別包的測試需要跟著改」的清單
4. `grep -rn "NT\\$" apps/` 應為 0 筆（前綴只准在 `money.ts` 裡加）
5. 後台首頁不再出現任何假數字的截圖
6. ③④ 若因為 BE-19 未落地而沒做，**明講「未做，等 BE-19」**，不要假裝做了
