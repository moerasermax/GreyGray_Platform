## 0. 事實（Leader 已用真瀏覽器 ＋ API 逐條查證，直接當前提）

### 畫面上看到的 vs 真實

2026-09-01 使用者登入後台後，Leader 用真 Chrome 逐頁測，發現首頁與帳務頁互相矛盾：

| | 儀表板首頁 `/` | 帳務頁 `/ledger` 與 API |
|---|---|---|
| 客戶負債 | **NT$1,280,000** | **NT$0** |
| 現金總額 | **NT$860,000** | **-NT$1,920** |
| 資料時間 | **2026年8月28日 上午9:15** | 2026年9月1日（即時） |
| 最近分錄 | 6 筆 `ORD-20260827-*`／`TRIP-2026Q3-JP01` | **只有 1 筆**（BE-38 的進貨分錄） |

`GET /v1/ledger/liability-vs-cash` 實際回傳（Leader 以 Owner 身分實打）：

```json
{"customerLiabilityTotal":{"amountMinor":0,"currency":"TWD"},
 "cashTotal":{"amountMinor":-192000,"currency":"TWD"},
 "asOf":"2026-09-01T12:43:01Z","isBreached":true}
```

### 根因

`apps/admin/app/(dash)/_lib/dashboardMock.ts` 的
`LIABILITY_VS_CASH_FIXTURE`（第 38 行起）與 `LEDGER_ENTRIES_FIXTURE`（第 57 行起）
是**寫死的 fixture**，被 `apps/admin/app/(dash)/page.tsx` 第 21-26 行直接 import 使用。

### ★ 那個檔案自己的註解就已經寫好答案了

`dashboardMock.ts` 開頭的註解寫著：

> 真正串接時要換成：
>   - `GET /v1/ledger/liability-vs-cash` → LiabilityVsCash
>   - `GET /v1/ledger/entries`（`sourceModule` / `from` / `to` 篩選）→ 分錄列表

**這兩個端點現在都存在也都正常**（Leader 實打皆 200 有真實資料），
而且 `packages/api-client/src/endpoints/admin.ts` 早就有對應函式：
`getLiabilityVsCash`（第 317 行）、`listLedgerEntries`（第 297 行）。

同一段註解還寫著 KPI 四塊拔掉假數字的理由：

> 營運會相信後台上的數字，**佔位值放在正式環境比沒有更危險**

**FE-16 為了這個理由拔掉了四個 KPI 假數字，卻把財務卡與分錄表留在假資料上。**
這一包就是把那個政策貫徹完。

## 4. 工作包

### FE-21　後台首頁接上真的帳務端點（#29）　🔴

**相依**：無　**獨佔**：見 §3

#### 必做 1　「負債 vs 現金」卡改用真資料

`(dash)/page.tsx`：把 `LIABILITY_VS_CASH_FIXTURE` 換成
`getLiabilityVsCash(browserApi())`，照 `(dash)/ledger/page.tsx` 的形狀，
**要有 loading 與 error 兩個狀態**——載入中不要顯示 0，失敗要說失敗，
**絕對不要 fallback 回任何寫死的數字**（那正是這個 bug 的成因）。

#### 必做 2　「最近分錄」表改用真資料

換成 `listLedgerEntries(browserApi(), …)`。
現有的三個篩選（來源模組、起訖日期）目前是在前端記憶體裡過濾 fixture，
**改成把條件送給端點**（`sourceModule`／`from`／`to` 都是既有 query 參數）。
排序與 Drawer 明細維持現有互動，資料來源換掉即可。

> 「相關分錄」那個 Drawer 現在用 `sourceRef` 在 fixture 裡撈同一張單的其他行。
> 端點支援 `sourceRef` 篩選，改用它。

#### 必做 3　把 fixture 從程式碼裡拿掉

`LIABILITY_VS_CASH_FIXTURE` 與 `LEDGER_ENTRIES_FIXTURE` **整段刪掉**，
不要留著「暫時不用但還在檔案裡」——留著就會有人再 import 一次。
`DASHBOARD_KPIS` 與 `DashboardKpi` **保留**（那是誠實的「尚未提供」，不是假數字）。
`dashboardMock.ts` 這個檔名若因此名不副實，可以改名，
但**改名就要把所有 import 一起改乾淨**，typecheck 要過。

#### 必做 4　補測試釘住「首頁不准出現寫死的金額」

在 `apps/admin` 加測試，至少涵蓋：

1. 給定一個 mock 的 `getLiabilityVsCash` 回應，畫面顯示的金額**等於該回應**
2. 端點失敗時**不顯示任何金額**（顯示錯誤狀態），而不是退回某個預設值

★ 這一條是這一包最重要的產出：**#29 能活到現在，是因為沒有任何測試斷言過
「首頁顯示的數字來自 API」**。沒有這條測試，改完還是會再退化。
