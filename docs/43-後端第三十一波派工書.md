## 5. 可能寫錯的地方（撞到就停下來問，不要自己換做法）

- **觸發點是「交運」不是「簽收」**：`docs/02` 第 ⑦ 階段兩筆都在出貨，而 `ShipmentDispatched` 的 XML doc 明寫 Ledger 訂閱它開運費成本。貨在交運時離開倉庫，所以出庫也在交運。不要改成 `ShipmentDelivered`。
- **一張出貨單可以合併多張訂單（N:M）**，`OrderIds` 是陣列；反過來一張訂單也可能拆進多張出貨單——這一包的冪等守衛（狀態已出庫就跳過）必須撐得住第二張出貨單也帶到同一個 orderId 的情況。`.dispatch/reports/` 底下 FE-27 那一包的說明有 N:M 的背景。
- **`Money` 乘法**：`TotalCost` 是單位成本 × 數量，用 `Money` 既有的運算（若沒有乘法 API，看 `Shared.Kernel` 裡怎麼做的，不要 `new Money(cost.AmountMinor * qty, …)` 繞過檢查）。撞到就停下來問。
- **`quantity_available` 是 generated column**：只寫 `quantity_on_hand` 與 `quantity_reserved`，寫 available 會直接被資料庫拒絕。
- **`AddIdempotentIntegrationEventHandler` 的去重範圍是 (event, handler)**，不是 (shipment, order)。同一個 `ShipmentDispatched` 重放會被擋，但「兩張不同的出貨單帶到同一個 orderId」不會——那要靠 reservation 狀態擋。
- **Ledger 的 `sourceRef` 會進 `journal_entry.source_ref`**，人要看得懂也要能追回來源；`StockCostAllocated` 的 `SourceRef` 是 Inventory 給的字串，直接沿用，不要再包一層。
