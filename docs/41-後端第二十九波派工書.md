## 1. 必做

### 必做 A　START 改看 SCM 狀態（`ops/lib/Deployment.ps1` ＋ `ops/deploy.ps1`）

1. `ops/lib/Deployment.ps1` 加 `Wait-ManagedServiceStart`：
   - 參數：`-ServiceName`、`-StartService <scriptblock>`（回 `Invoke-NativeCommand` 那個 result 物件或 `$null`）、`-GetStatus <scriptblock>`（回 `[System.ServiceProcess.ServiceControllerStatus]`）、`-TimeoutSeconds`（`[ValidateRange(5, 180)]`）、可選 `-PollMilliseconds`（預設 500）。
   - 邏輯：呼叫 `-StartService`（**不管它的 ExitCode**，但把 StdOut／StdErr 留著給錯誤訊息用）→ 輪詢 `-GetStatus`：`Running` 就回傳（回 `[pscustomobject]@{ ServiceName; Status; StartExitCode; Elapsed }`）；`StartPending` 繼續等；到期還不是 Running 就 throw，訊息含服務名、最後狀態、nssm 的 ExitCode 與輸出。
   - `Stopped` 一路到期也是 throw（不要因為 exit 0 就算過）。
   - 若 `-StartService` 回的 ExitCode ≠ 0 但最後 Running：`Write-Host` 一行警告（把 nssm 原話印出來），**不 throw**——這就是 0.1 那個案例。
2. `ops/deploy.ps1` 第 472-475 行改成對每個服務呼叫 `Wait-ManagedServiceStart`：
   - `-StartService { Invoke-Nssm -Arguments @('start', $名稱) -AllowNonZeroExit }`（plain scriptblock；`$名稱` 用迴圈外先存成變數的方式讓 scriptblock 看得到——照第 405-425 行 `$serviceNameForGet` 的既有做法）。
   - `-GetStatus { $s = Get-Service -Name $名稱; $s.Refresh(); $s.Status }`。
   - `-TimeoutSeconds $HealthTimeoutSeconds`。
   - `$restartBoundaryUtc` 仍在 START 之前取（第 472 行位置不動）。
3. **`Invoke-Nssm -Arguments @('start', …)` 在 `deploy.ps1` 裡一律要帶 `-AllowNonZeroExit`**（必做 C 會用 AST 釘住）。

### 必做 B　部署期間暫停 watchdog（`ops/lib/Deployment.ps1` ＋ `ops/deploy.ps1`）

1. `ops/lib/Deployment.ps1` 加 `Suspend-WatchdogTask` 與 `Resume-WatchdogTask`，決策邏輯全部吃注入的 scriptblock（`-GetTask`、`-StopTask`、`-DisableTask`、`-EnableTask`），deploy.ps1 傳真的 `Get-ScheduledTask`／`Stop-ScheduledTask`／`Disable-ScheduledTask`／`Enable-ScheduledTask`：
   - `Suspend`：`-GetTask` 回 `$null`（第一次部署、還沒登記）→ 回 `$false`、什麼都不做；State 是 `Running` → 先 `-StopTask` 再 `-DisableTask`；其他 → `-DisableTask`；回 `$true` 表示「我停用了、結束要恢復」。
   - `Resume`：只有 `Suspend` 回 `$true` 才呼叫 `-EnableTask`。
2. `ops/deploy.ps1`：在 STOP 迴圈（第 327 行 `$oldTokens = …` 之前）呼叫 `Suspend-WatchdogTask`，把 STOP → 參數 → START → `Assert-NewApplicationProcess`（到第 538 行）整段包進 `try { … } finally { Resume-WatchdogTask … }`——**失敗也要恢復**，不然一次失敗的部署會讓正式機從此沒有 watchdog。
3. 第 565 行 `Register-ScheduledTask -Force` 保留（它會以啟用狀態重登記），放在 `finally` 之後原位即可。
4. `-ValidateOnly` 路徑不准碰排程（它本來就在動 NSSM 之前 return，確認 `Suspend` 的呼叫點在那個 return 之後）。

## 5. 可能寫錯的地方（撞到就停下來問，不要自己換做法）

- `ServiceController.Status` 是快取，輪詢前一定 `Refresh()`；`WaitForStatus` 也可以用，但 5.1 與 7 的逾時例外型別不同（`System.ServiceProcess.TimeoutException`），自己輪詢比較好控制訊息。
- nssm 的輸出在 5.1 下可能夾 NUL 字元（Leader 在 YC 看過 `?` 與 `\0`），拿來比對「已在執行中」時先 `-replace '\0',''`，而且**不要拿字串比對當成功條件**——成功條件只有 `Running`。
- `ScheduledTasks` 模組在 pwsh 7 走 Windows PowerShell 相容層，self-test 不准呼叫真的 `*-ScheduledTask`（需要管理員、也慢），只測注入的 scriptblock；deploy.ps1 那邊才傳真的 cmdlet。
- `Disable-ScheduledTask` 之後 `Register-ScheduledTask -Force` 會以 XML 內 `<Enabled>true</Enabled>` 重登記為啟用——所以 `finally` 的 `Resume` 與最後的 `Register` 兩者都在時不會衝突；但**失敗路徑只有 `finally` 會跑**，這就是為什麼 `Resume` 一定要在 `finally`。
- 第 405-425 行的 `$serviceNameForGet` 做法（迴圈變數複製一份給 plain scriptblock 用）是為了避開 `GetNewClosure()`；新 scriptblock 照抄那個模式，別發明第三種。
