## 1. 要做什麼

### A. `/me`——「我的」總覽頁（主要交付）

`apps/storefront/app/(account)/me/page.tsx`（新檔）：

1. 載入 `getMe`；401 → 導去登入並帶 `next=/me`（見 C）；其他失敗 → `ErrorState` 可重試。
2. 內容：`<h1>` 「我的」；顯示 `displayName`、`phoneNumberMasked`、有 `email` 就顯示；
   三個入口（都是 `next/link`）：**我的訂單** → `/orders`、**收件地址** → `/addresses`、**儲值金** → `/wallet`。
3. **「登出」按鈕**：呼叫 `logout`（要冪等鍵），成功 → `router.replace('/')`；失敗顯示訊息、留在原地。
4. 有分頁列（預設就有），而且「我的」分頁在這一頁要亮著。
5. 版面照 `(account)/wallet/page.tsx` 與 `(account)/orders/page.tsx` 的既有語彙（`Card`、token 間距），不要發明新樣式。

### B. 「我的」改指 `/me`

- `apps/storefront/app/_lib/tabs.ts` 的 `STOREFRONT_TABS`：「我的」`href` 改 `/me`，`alsoActiveFor` **加** `/orders`（其餘四個保留）。
  順手把第 118-119 行那段「因為前台沒有帳號首頁」的註解改成現況。
- `HomeSearchHeader.tsx:22` 的頭像 → `/me`。
- `payment/result/page.tsx` 的「查看我的訂單」維持 `/orders`（那個情境要看的就是訂單）。
- `tabs.test.ts` 兩段斷言改成新目標，並**加** `/me` 的案例（顯示分頁列、亮「我的」）。

### C. 登入後回到原頁（`?next=`）

- `apps/storefront/app/_lib/auth.ts`（新檔）兩個純函式：
  - `safeNext(raw: string | null | undefined): string`——只接受**站內絕對路徑**（以單一 `/` 開頭、不是 `//`、沒有 scheme、沒有 `\`），
    其他一律回 `/me`。
  - `loginHref(next: string): string`——組 `/login?next=<encodeURIComponent(next)>`。
- `apps/storefront/app/_lib/__tests__/auth.test.ts`（新檔）：`//evil.com`、`https://evil.com/x`、`javascript:alert(1)`、`\\evil`、空字串、`null`
  → 都回 `/me`；`/checkout`、`/orders/abc?x=1` → 原樣；`loginHref('/checkout')` 的 `next` 要能被 `safeNext` 解回來。
- `/login` 與 `/register`：成功後 `router.push(safeNext(searchParams.get('next')))`（不再寫死 `/orders`）；
  兩頁互連的連結（登入 ↔ 註冊）要把 `next` 帶著。`useSearchParams` 照 0.5 的 Suspense 前例。
- 需要登入的頁（`/me`、`/orders`、`/orders/[orderId]`、`/addresses`、`/wallet`）401 時
  `router.replace(loginHref(現在的 pathname + search))`。
- **結帳頁**送出撞 401 → `router.push(loginHref('/checkout'))`，不是只顯示錯誤；
  **付款頁**初始化撞 401 → `router.push(loginHref('/payment/<orderId>'))`。購物車 cookie 不受登入影響，回來東西還在。

### D. 付款結果頁自動重查

- `apps/storefront/app/(checkout)/_lib/paymentResultPolling.ts`（新檔）純函式：
  `POLL_DELAYS_MS` 是**有限、遞增**的排程（建議 `[1000, 2000, 3000, 5000, 8000]`，總共 5 次、19 秒內），
  `shouldKeepPolling(status, attempt)` 只在 `AwaitingPayment` 且還有排程時為真。
- `payment/result/page.tsx`：狀態是 `AwaitingPayment` 時照排程重查；狀態變了就停；排程用完就停並顯示**「重新查詢」按鈕**；
  重查期間文案「正在向付款服務確認……」。不是 `AwaitingPayment` 不重查。**不要無限輪詢。**
- `apps/storefront/app/(checkout)/_lib/__tests__/paymentResultPolling.test.ts`（新檔）：排程有限且遞增；
  `AwaitingPayment` 以外任何狀態都不重查；用完排程回 `false`。
