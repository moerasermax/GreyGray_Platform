# FE-38 前台視覺精修

2026-09-21，使用者授權與 AI-CLI Claude-Fable 繼續美化，要求更俐落、專業。此為 ADR-009 的視覺演進，保留粉紅識別、圓角與 mobile first；不再要求整頁粉底粉字。

## 現況證據與目標

現有 token 同時把背景、文字、邊框與陰影設成粉色，首頁僅搜尋列、活動橫幅、分類和商品牆。活動圖在手機只有 64px，沒有開團時整段主視覺消失。目標是完整、有品牌感的選品店首頁，搭配全站一致的中性閱讀層級。

暖白背景、深灰正文、低彩度邊框，粉紅集中於互動與品牌識別；減輕陰影、收斂大圓角。首頁增加可識別的品牌標頭、清楚的瀏覽入口、具視覺份量的活動區和商品區標題。不使用空泛的數據、保證或假促銷。

## 所有權（FE-38，單一實作者）

- `frontend/packages/ui/src/tokens/soft-seoul.css`：全站前台配色與視覺尺度，同步更正舊註解；不修改 admin tokens。
- `frontend/apps/storefront/app/(shop)/_components/HeroBanner.tsx`：響應式主視覺、開團封面與明確入口；沒有活動時仍提供誠實的品牌介紹和逛商品入口。
- `frontend/apps/storefront/app/(shop)/_components/HomeSearchHeader.tsx`：品牌、導航、搜尋與會員入口；保留既有搜尋行為。
- `frontend/apps/storefront/app/(shop)/page.tsx`：頁面留白、段落層級與查看全部連結；保留 API 呼叫、分類、商品牆與資訊頁連結。
- `.dispatch/reports/FE-38.md`：自驗證據與未驗項目。新檔。

每次編輯前備份到工作區外的獨立臨時目錄，記錄位置。現有 FE-37 與閘門變更屬於基線，禁止還原、提交或冒認。不得修改 GreyGray_PM、契約、API、金額或交易行為；不安裝套件、不啟停服務、不部署、不開子代理。

## 驗收

1. 實作者執行 storefront 與 ui 的 typecheck、既有 storefront 測試，前景等到結束，記錄實際指令、數字與退出碼。最多兩輪修正。Leader 負責 build，先確認不會干擾運行中的 dev。
2. Leader 以實際瀏覽器查看首頁、商品列表、詳情、購物車，涵蓋手機 390px 與桌面 1440px；檢查無水平溢出、無遮擋，導航以點擊驗證，避免只靠直達 URL。
3. 驗證有活動、無活動、長標題與缺封面；不可因無活動讓主要瀏覽入口消失。若實際資料無法覆蓋，使用既有渲染測試方法並明列限制。
4. 重新計算正文、次要文字、主按鈕與 banner 的對比度（一般文字至少 4.5:1）。保持可見 focus、44px 觸控目標、reduced-motion、語意標題。
5. 金額、購物車、登入與付款不在本包業務修改範圍；不進行真實下單付款。前台 token 改動須目視回歸其他頁，後台不得變色。

## 邊界分類

上下限：390px/1440px、長標題、空活動。部分失敗：無封面／空資料仍可導航。重複與併發、非法狀態轉移、權限、事件重放：本包不改資料寫入與狀態機，沿用既有測試，不以視覺驗收冒稱交易驗收。

## 交付與後續

自驗不是整合通過。Leader 看過畫面與差異後再驗收。若共用商品卡／分類／底部導航仍與新版不協調，後續另開明確包；不能因此縮小「整體更專業」的原目標。未經驗證不得宣稱完成或已上線。
