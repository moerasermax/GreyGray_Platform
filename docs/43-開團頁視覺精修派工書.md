# FE-41 開團頁視覺精修

## 目的與已觀察證據
延續使用者要求的俐落專業前台，沿用暖白、深灰、克制粉紅。Leader 2026-09-21 真瀏覽器由開團列表卡片進入詳情：缺圖卡片仍有大塊空白；桌面詳情全寬16:9空封面佔據首屏大部分，團名與品項被推到底下。現有測試旅程為 Seoul，已截止且品項 disabled。Leader 隨後以390x844窄版實測：品項縮圖、文字、控制同列，完整品名「韓國雪花秀 潤燥精華液」被壓到只顯示「韓國雪花…」，數量控制佔去近半列；需要手機分行。

## 要求
1. 開團卡片：有圖保留 Thumbnail；缺圖以既有目的地與中性圖形排版、清楚說明封面尚未提供，不捏造旅遊照片。避免手機正方形大空白。卡片高度、留白、標題與日期層級、整卡 focus-visible 清晰；長團名及目的地可折行。維持整卡 Link 與現有狀態 badge/countdown。
2. 詳情頁：桌面封面與資訊雙欄，手機合理橫幅比例；封面不再佔滿首屏，把團名、目的地、出返日期、倒數與收單提示放在易讀位置。缺圖用同一種設計語彙。描述保留完整且長文字可折行。團購品項獨立清楚的 section；無品項提示保留。SSR、metadata、404、資料讀取不改。
3. 品項列：縮圖與文字有穩定比例及 min-width；手機把數量、加購與禁用原因放在下一行，桌面可同列，長品名、規格、unitPriceLabel、金額不能擠壓控制或溢出。缺圖有中性辨識。禁用/載入/錯誤/成功提示與查看購物車入口均保留。Toast 若調整位置，只能使用現有底部分頁列高度與 safe-area token，不能猜固定高度。
4. 僅展示調整：不得修改 isAcceptingOrders、status、時間與下架判斷、QuantityStepper 1..99、請求 payload、冪等鍵、publishCart、收藏或金額計算。badge 與已截團可能同時存在，不在本包重新定義業務狀態。不能改共用 UI、列表分頁、測試期望或其他包。
5. 使用現有 token 與既有依賴，不加 raw hex、任意像素、假資料、抽象或新套件。保留主要導覽、客服按鈕與底部內容安全留白，驗收必須透過可見連結。
