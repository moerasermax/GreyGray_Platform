## 實作要求
1. 商品卡：缺圖用中性、完整的品牌排版／簡潔圖示及「商品圖片待補」文字，不留純空白，不捏造商品照片；有圖仍使用 Thumbnail 與 1:1 裁切。商品名稱至少兩行，長字串可折行，縮小手機卡內無效留白，圖片與資訊分層，收藏不遮名稱。
2. 未定價卡保持可瀏覽、可取消收藏及既有不可購買提示；媒體比例、標題與卡片高度節奏和有定價卡一致，不偽造價格，不改收藏狀態機、toast、登入重導與 suppressCardNavigation。
3. 分類缺圖不能是空圓：用有語意的簡潔通用圖示或文字圖形；名稱可兩行，完整可及名稱，44px 最小觸控，選取態与 focus 清楚，不猜分類業務或把按鈕包進連結。
4. 導覽保留四入口、路由顯示規則、aria-current、即時購物車件數與 TAB_BAR_HEIGHT / SAFE_AREA 算式。手機保留四等分；桌面把項目集中於有限寬度，圖文橫排或適當間距，柔和 active 底色與明確 focus，避免全螢幕四個孤立圖示。不得改成隱藏導覽或遮住底部動作列。
5. 顏色與尺寸用既有 token；無新依賴，無 API/金額/契約/交易變更；保留 FE-37/FE-38 與既有 dirty worktree。僅備份自己的四個原始碼到 TEMP，列路徑後再改。

## 驗證
實作者在 frontend 前景執行 ui/storefront typecheck、既有 storefront test，最多兩輪，不開關 dev server、不 build、不提交不部署、不開子代理。若渲染純展示元件可用既有工具在臨時檔驗證缺圖/長標題，不新增依賴或為湊數寫鏡像測試。

重複與併發／權限／狀態轉移／事件重放／部分失敗：沿用現有收藏與購物車測試，不聲稱交易驗收；新變更只展示層。
