### #31 的事實（順手修）

`packages/ui/src/components/Countdown.tsx:29`：`useState(() => Date.now())`。
伺服器算一次、瀏覽器 hydration 時再算一次，**兩邊的秒數不同**，React 判定文字不一致，
把整棵樹丟掉重建（2026-09-02 console 逐字證據：`+137:02:24` / `-137:02:25`）。
功能沒壞，但每次載入多一次整頁 client 重建，而且 hydration 錯誤會遮蔽真正的錯誤。

用到它的：`apps/storefront/app/(shop)/campaigns/[campaignId]/page.tsx`（開團詳情）
與 `apps/storefront/app/(shop)/_components/CampaignCard.tsx`（開團列表 `/campaigns` 的卡片）。

## 1. 要做什麼（使用者 2026-09-02 拍板：這三頁加一條頂部列）

### A. 三頁的頂部列——主要交付

左邊「返回」、中間頁名、商品頁右邊放帶徽章的購物車圖示。
`position: sticky; top: 0`（不是 fixed，才不用再去 body 補頂部留白），
z-index 用已經存在的 `--gg-z-header`，含 `env(safe-area-inset-top)`。

**五個結果要成立，而且要可測（機制你決定）：**

1. **每一條路由恰好有一種殼**：分頁列或頂部列，二擇一。分頁列隱藏的頁面就要有頂部列，
   反之亦然。唯一的例外是 `/payment/:orderId`（那一頁自動 POST 導轉綠界，兩種都不放），
   例外要像 `TAB_BAR_RULES` 一樣**寫得出理由**。
   ★ 測試要用 `bottomActionBarCollision.test.ts` 那種做法——**去原始碼裡真的掃**每一個
   頁面檔案、推出路由、逐條斷言——而不是再抄一份清單。掃到零個要算失敗。
2. **返回在「直接打網址進來、沒有上一頁」時也要有地方去**：
   商品詳情 → `/`、購物車 → `/`、結帳 → `/cart`。返回必須是真的 `<a href>`（`next/link`），
   沒有 JS 也能走、鍵盤也到得了；有站內上一頁時可以攔下來走 `history.back()`，
   但後備目標要用測試釘住。
3. **標題**：商品頁＝商品名（單行、超出截斷）、購物車＝「購物車」、結帳＝「結帳」。
   頁面既有的 `<h1>` 不動，頂部列的標題不是另一個 `<h1>`。
4. **商品頁右邊的購物車圖示**：連到 `/cart`，徽章與可及名稱跟分頁列**同一套函式、同一份 store**
   （拿不到就不畫、永遠不退化成 0、唸「購物車，X 件」）。加入購物車後它要跟分頁列一樣就地更新。
5. **兩條列不可以蓋住內容**：`body` 的 `padding-bottom` 維持 72px（`globals.css:88` 不動），
   頂部列用 sticky 就不需要頂部留白。

**建議的切法**（不是硬性規定，但偏離要在報告裡說明理由）：
`packages/ui/src/components/TopBar.tsx`（新檔）只管長相——左／中／右三個 slot、token、sticky、safe-area，
不碰 router；`apps/storefront/app/_components/PageTopBar.tsx`（新檔）管行為——返回目標、
購物車徽章。三頁各自渲染 `<PageTopBar>`（標題是頁面資料，商品名只有那一頁知道）。
判斷邏輯抽成 `apps/storefront/app/_lib/` 的純函式，測試放 `apps/storefront/app/_lib/__tests__/`，
因為 `packages/ui` 沒有 vitest，寫在那裡的測試永遠不會跑（FE-22 踩過）。

**圖示**：把 `TabBarIcons.tsx` 的四顆搬進 `packages/ui/src/components/icons/index.tsx`
（照那個檔的命名與規格），分頁列與頂部列的購物車圖示用**同一顆**。搬完 `TabBarIcons.tsx`
要嘛刪掉、要嘛只剩轉出，不要留兩份 SVG。

### B. 提示加「查看購物車」

`Toast` 加一個**選填**的動作 prop（例如 `action?: { label: string; href: string }`），
畫成連結。**有動作的提示要留得夠久讓人按得到**——2.5 秒不夠，建議有動作時 5 秒。
商品頁（`AddToCartPanel.tsx:150`）與開團頁（`CampaignOfferRow.tsx:89`）的成功提示都加上
「查看購物車」→ `/cart`。後台的用法不變。

### C. #31 順手修——次要、可分離

讓伺服器**不要算即時值**：初始 `now` 在伺服器與瀏覽器第一次渲染都是「還不知道」，
畫一個寬度穩定的佔位（維持 `tabular-nums`），掛載後才開始每秒更新。
`isAcceptingOrders` 的語意不變（能不能下單永遠不看倒數）。
**如果做起來牽動的東西比預期多，停下來寫進報告，不要讓它拖住 A 與 B。**

### 不要做的事

- **不要動後端、不要動 `docs/api/*.yaml`**
- **不要加相依套件、不要動 `pnpm-lock.yaml`、不要動任何 `package.json`**
  （這個 workspace 沒有 jsdom／`@testing-library`，測試走純函式與原始碼掃描）
- **不要動 `apps/storefront/app/globals.css`**（`body` 的留白現況是對的）
- **不要改 `TAB_BAR_RULES` 的結果**：分頁列在哪些頁隱藏維持原樣。既有 248 條測試一條都不能改掉
- **不要做全站頂部頁首**：使用者拍板的是只有這三頁，首頁與列表頁維持只有分頁列
- **不要改三頁的版面與邏輯**：只加頂部列與提示動作
- **`/payment/:orderId`、`/payment/result` 不動**
- **★ 不要跑 `next build`**：dev server 正在跑，兩者共用 `.next`，build 會把 dev 的 manifest 抽掉、
  整站變成裸的 500（2026-09-02 踩過）。typecheck 與 vitest 就夠，build 由 Leader 在驗收時跑
- `packages/ui/src/components/` 的 allow 給的是整個目錄（因為 `TopBar.tsx` 還不存在），
  **但只准動 §3 點名的那幾個檔**，其餘檔案動了會在 `git diff` 逐檔審查時被退回
