## 1. 必做

### 必做 1　`ReturnURL` 可由 `Storefront:PublicApiOrigin` 指定；沒設就維持現狀

- `GreyGray.Api.Storefront/M1aEndpoints.cs`：把第 835 行那句抽成 `internal static Uri BuildEcpayReturnUrl(IConfiguration configuration, HttpRequest request)`：
  - 設定 `Storefront:PublicApiOrigin` **有值** → 必須是絕對網址、scheme 是 http 或 https、去掉結尾斜線，回 `{origin}/v1/webhooks/ecpay`；格式錯就 `InvalidOperationException`（訊息寫清楚鍵名與要求，比照 `BuildPaymentResultUrl`）。
  - **沒設** → 跟現在一樣 `{request.Scheme}://{request.Host}/v1/webhooks/ecpay`（dev 模擬器靠這個）。
  - 不要順手把 `Storefront:PublicOrigin` 改成也可省略——那是 #33 拍板過的形狀。
- 測試（`tests/GreyGray.M1a.CheckoutOrdering.Tests/`，新檔）：有設 → 用設定值、結尾斜線被去掉；沒設 → 用請求的 scheme/host；設成相對路徑或 `ftp://` → 丟例外且訊息含鍵名。
- 順手在 `ops/start-dev-hosts.ps1` 加選填參數 `-StorefrontPublicApiOrigin`（有給才注入 `Storefront__PublicApiOrigin`；預設不給，dev 行為不變）。

### 必做 2　`deploy.ps1` 投遞兩個公開 origin

- `param` 加 `[Parameter(Mandatory)][string]$StorefrontPublicOrigin` 與 `[Parameter(Mandatory)][string]$StorefrontPublicApiOrigin`（`-ValidateOnly` 也要驗：絕對 https 網址、無結尾斜線，不合就 throw）。
  Mandatory 是刻意的：正式機不准猜網址（跟 #33「不預設 localhost」同一個原則）。
- 只注給 **`GreyGray-Storefront`** 那個服務（第 359-363 行那段附近，依 `$definition.Name` 判斷）：`Storefront__PublicOrigin`、`Storefront__PublicApiOrigin`。Admin／Worker 不需要。
- 保持 5.1 可執行：不用 `??`、`?.`、三元運算子、`#Requires -Version 7`。
- `docs/14-環境整備runbook.md` 加一節「部署五個 app 服務」：完整指令（`ArtifactRoot`、`InstallRoot C:\GreyGray`、`NssmPath C:\GreyGray\bin\nssm.exe`、`ServiceCredential`、`MigrationCredential`＋`MigrationFiles`、
  `StorefrontPublicOrigin https://greygray.shop`、`StorefrontPublicApiOrigin https://greygray.shop`）、`secrets\ecpay.json` 的格式與「先用綠界公開測試店」的說明、以及 artifact 怎麼從開發機送到 YC（robocopy／scp 皆可，寫一種）。

### 必做 3　`build-frontends.ps1` 能建另一棵樹、能指定各 app 的 API base

- 加參數：`-FrontendRoot`（預設維持 `$repo\frontend`）、`-StorefrontApiBaseUrl`、`-AdminApiBaseUrl`。
  非 `-ValidateOnly` 時兩個 URL **必填**且要是絕對 http(s) 網址——正式 artifact 不准默默吃到 `.env.local` 的開發機位址。
- 建置分兩步：`pnpm --dir <FrontendRoot> --recursive --filter ./packages/* build` 一次；然後兩個 app **各自** `pnpm --dir <FrontendRoot> --filter @greygray/<app> build`，
  各自帶環境變數 `NEXT_PUBLIC_API_BASE_URL=<該 app 的值>` 與 `NEXT_PUBLIC_USE_MOCK=0`。環境變數只在那一次呼叫期間存在（設完就還原成原本的值／刪掉，**不要留下空字串**——#38 的教訓：用 `$null` 還原會變成空字串，要用 `Remove-Item Env:`）。
  `ops/lib/Node.ps1` 的 `Invoke-PnpmCommand` 若要加 `-Environment` 參數就加，5.1 可讀。
- 建完後**驗證 artifact 真的吃到那個值**：在 `<OutputRoot>\GreyGray.Web.Storefront\apps\storefront\` 的 `.next\server` 或 `server.js` 相關 chunk 裡 grep 到 `StorefrontApiBaseUrl` 的字串、且 grep **不到** `127.0.0.1:5000`；admin 同理。grep 不到就 throw（artifact 不可部署）。
- `-ValidateOnly` 印出解析後的 `FrontendRoot`、兩個 URL、node／pnpm 路徑，不執行 install／build。
- `ops/build.ps1 -Publish` 把新參數傳下去（`-FrontendRoot`／`-StorefrontApiBaseUrl`／`-AdminApiBaseUrl`），沒給就明確 throw（不准建出指向開發機的 artifact）。
