## 0. 事實（Leader 2026-09-15 查證）

### 0.1 流程長什麼樣子（ADR-038 決定 2）

```
結帳頁「選擇門市」
  → POST /v1/logistics/cvs-map-sessions        回 { selectionId, method, action, fields, expiresAt }
  → 隱藏表單頂層自動送出到 action（綠界地圖；dev 是模擬器的假地圖）
  → 客人在綠界選門市
  → 綠界經瀏覽器 POST 到後端（不是前端的事）
  → 後端 303 回到 /checkout?cvsSelection=<票>   或   /checkout?cvsSelectionError=<代碼>
  → GET /v1/logistics/cvs-selections/{票}      回 { storeCode, storeName, storeAddress, isOutlying, expiresAt }
  → 送出訂單帶 convenienceStoreSelectionId（不再送 convenienceStoreCode）
```

- **整頁離開結帳頁再回來**：頁面狀態全部消失。配送方式、出貨方式、地址、留言要靠既有的 `checkoutDraft`（`sessionStorage`）帶回來。
- 手機不可放 iframe、iOS 不要開新視窗：**同一個分頁頂層導向**（ADR-038 查證過的外部事實）。
- `cvsSelectionError` 的代碼（後端 `docs/52` §0.3 定的，**照這份顯示**）：

| 代碼 | 顯示 |
|---|---|
| `expired` | 門市選擇已逾時，請重新選擇門市。 |
| `already-used` | 這次的門市選擇已經用過了，請重新選擇門市。 |
| `invalid-reply` | 門市資料驗證失敗，請重新選擇門市。 |
| `not-configured` | 目前暫停超商取貨，請改選其他配送方式。 |
| `unavailable` | 暫時無法取得門市資料，請稍後再試。 |
| 其他任何值 | 門市選擇沒有完成，請重新選擇門市。 |

- 其他錯誤：`cvs-map-sessions` 回 `503 logistics.not-configured` → 同上表 `not-configured` 那句；送出訂單回 `422 checkout.store-selection-expired` → 清掉目前的門市、顯示 `expired` 那句；讀票 `404` → 清掉、顯示 `expired` 那句。
