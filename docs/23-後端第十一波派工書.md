  <ProjectReference Include="..\..\Modules\Identity\GreyGray.Modules.Identity.Infra\GreyGray.Modules.Identity.Infra.csproj" />

**只參考 Identity.Infra，不要多拉其他模組**——這支工具唯一要做的事是建員工帳號，
拉進其他 12 個模組的 Infra 只會增加它在 DI 解析期失敗的面（例如缺 `ConnectionStrings:GreyGray_payment`

```csharp
var builder = Host.CreateApplicationBuilder(args);

builder.Services.AddIdentityModule(builder.Configuration);
var host = builder.Build();

// 解析參數、讀種子清單、逐筆呼叫 IStaffAccounts.CreateAsync，見下方行為規格
// 跑完印摘要、回傳 exit code，不要呼叫 host.RunAsync()——這是一次性工具，不是常駐服務
```

**命令列參數**（用 `args` 自己 parse，不需要拉 `System.CommandLine` 這種新依賴，
簡單的 `--key value` 掃描就夠）：

- `--seed <path>`：必填，種子清單 JSON 路徑
- `--secrets-dir <path>`：必填，讀 `ConnectionStrings__GreyGray_iam` 與
  `Identity__DataProtectionKey`（由外層腳本先設好環境變數，這支工具**不直接讀
  `secrets-dir` 底下的檔案**——env var 由 `ops/seed-dev-staff.ps1` 負責組好，
  這支工具只負責「有 config 就用」，跟三個既有 Host 的職責邊界一致）以外，
  拿來當「這次新建立的帳號密碼要寫到哪」的輸出目錄

**行為規格**：

1. 讀 `--seed` 指到的 JSON（格式見必做 2），每筆是 `{ "displayName", "email", "role" }`。
   `role` 是字串（`"Owner"`／`"Operator"`／`"Accountant"`／`"ReadOnly"`），用
   `Enum.Parse<StaffRole>(value, ignoreCase: true)`。
2. 對每一筆：產生一組隨機密碼（`RandomNumberGenerator.Fill` 24 bytes → Base64，
   長度落在 `CreateStaffInput` 要求的 8～128 字元內，見 §1 那條密碼字元替換的說明），
   在一個 `IServiceScope` 裡解析 `IStaffAccounts`，呼叫
   `CreateAsync(new CreateStaffInput(displayName, email, generatedPassword, role), ct)`。
3. `Result` 是 `Success`：這筆算「新建立」，把 `{ email, displayName, role, password }`
   放進「本次新建立」清單。
4. `Result` 是 `Failure` 且 `ErrorCode == "identity.staff-email-conflict"`：這筆算
   「已存在，略過」，**不是錯誤**——冪等的核心就在這裡，工具要能安全重跑。
5. `Result` 是其他任何 `Failure`：這是真的錯誤（例如種子清單本身格式不對、
   `displayName` 超長），印出 `ErrorCode` 與訊息，整支工具最後用非 0 exit code
   結束，不要吞掉。
6. 全部跑完後，把「本次新建立」清單（含明文密碼）寫進
   `<secrets-dir>\staff-credentials.json`：如果檔案已存在，**合併**（保留舊帳號的
   既有紀錄，只把這次新建立的加進去，不要覆蓋整個檔案——理由：如果之前跑過一次
   已經留下 3 筆，這次只新建了第 4 筆，舊 3 筆的密碼紀錄不該被清掉）。
7. Console 輸出只印 email／displayName／role／「新建立」或「已存在」，
   **不要把密碼印到 console**——這支工具的 stdout 會被自驗流程截下來，
   密碼要嘛不看、要嘛只在寫進去的檔案裡看得到，跟 `docs/22`「不要把金鑰內容
   貼進報告」同一個理由。
