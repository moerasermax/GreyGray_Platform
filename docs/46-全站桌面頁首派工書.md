# FE-44 全站桌面頁首

## 證據與範圍
Leader 2026-09-24 以 headless Chrome 1440 寬實際截圖：只有首頁有品牌頁首（`HomeSearchHeader`：品牌、搜尋、全部商品／開團／購買流程／常見問題、會員）；`/products`、`/terms`、`/login` 等其他頁在桌面沒有任何品牌或頂部導覽，只剩螢幕底部的手機式分頁列，而且在 `/products` 上亮的是「首頁」。桌面看起來像放大的手機 App，這是使用者要求「專業感」的最大缺口。
知識庫前例（e6619bdf，#30／#32）：前台曾兩度出現「頁與頁之間沒有路」——拿掉任何導覽之前必須先有替代出口，且要用畫面走、不能跳網址。本包的原則因此是**桌面（lg 以上）換成頂部頁首，手機（lg 以下）完全不變**。
沿用 FE-38 定案的暖白、深灰、克制粉紅 token，不新增 token、不改共用 UI 元件。

## 要求
1. 新增 `SiteHeader`（client component），只在 `lg` 以上顯示（`hidden lg:block`），掛在根 layout `{children}` 之前。內容：左側品牌（沿用 `HomeSearchHeader` 的品牌標記寫法，連回 `/`）、中間 `SearchBar`（行為與首頁搜尋相同，不改搜尋邏輯）、右側導覽「全部商品／開團／購買流程／常見問題」＋購物車（含件數徽章，重用 `useCartItemCount`、`formatCartBadge`、`cartTabAccessibleName`，不自己算數字）＋會員入口（`/me`）。目前所在頁用 `aria-current="page"` 與既有選中樣式標示；判斷用 `usePathname`，前綴規則要讓 `/products/*`、`/categories/*` 亮「全部商品」，`/campaigns/*` 亮「開團」，`/cart`、`/checkout` 亮購物車。
2. `SiteHeader` 在 `/payment/:orderId` **不顯示**（理由同 `_lib/tabs.ts` 的 `TAB_BAR_RULES`：該頁自動導轉綠界，不能讓人中途切走）；直接用既有 `tabBarRuleFor(pathname)` 判斷該路由，不要另寫一套路由比對。其他頁一律顯示。
3. 頁首內層寬度對齊既有 `--gg-container-max`、左右 padding 用既有 spacing token；`sticky top-0`、白底、底部細邊框（`border-border-soft`），z-index 用 `--gg-z-header`。不要加陰影堆疊、漸層或裝飾圖。
4. 底部分頁列在 `lg` 以上隱藏：在 `StorefrontTabBar` 的 `<nav>` 加 `lg:hidden`。**不得**更動 `TAB_BAR_HEIGHT`、`globals.css` 的 body padding 算式或 `tabBarReservesBottomSpace` 測試；桌面底部因此多出的 72px 留白可接受，寫進報告即可。
5. `PageTopBar`（商品詳情／購物車／結帳）在 `lg` 以上隱藏：透過 `TopBar` 既有的 `className` 屬性傳 `lg:hidden`，**不要**外包一層 div（會讓 `sticky` 在手機失效）。這三頁在桌面的出口改由 `SiteHeader` 提供（品牌回首頁、購物車、全部商品）。
6. `HomeSearchHeader` 在 `lg` 以上隱藏（首頁桌面改由 `SiteHeader` 負責，避免雙頁首）；手機版的結構、搜尋與會員入口原樣保留。
7. 根 layout 的 `viewport.themeColor` 從舊粉 `#fdf2f8` 改成 FE-38 的 `--gg-bg` 值 `#faf8f6`（這是 metadata 字串，無法引用 CSS 變數）。
8. 所有連結可用鍵盤到達、焦點框可見（沿用既有 focus ring 寫法）；觸控區至少 `--gg-touch-min`。不動 `SupportWidget`、`BottomActionBar`、任何 API、購物車 store、交易流程。
