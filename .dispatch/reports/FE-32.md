## 逐條自驗

1. api-client：前置為 Leader 已同步新契約；執行 codegen，再檢查 admin 型別差異；結果 storefront 型別新增三條 operation，`types.admin.ts` 零 diff。三支 endpoint 的 query、response、path id 都直接從 `paths[...]` 推導；mock 驗了首頁／末頁、最新在前、未定價商品、PUT 重放、DELETE 重放、合法但不存在 id 的 204、格式錯誤的 404、PUT 404 與列表 422。完整 recursive 後補上 DELETE 格式邊界，只重跑 api-client 自己的測試（40 條），沒有重跑共享的 recursive 驗證。
2. 重複與併發：前置為 request promise 尚未完成；同一個 tick 同步呼叫兩次；最愛只呼叫 mutation 一次，購物車兩種按鈕互搶也只呼叫 addLine 一次且只有第一個意圖的 callback 執行。拿掉兩處同步鎖後測試分別紅 1 條與 2 條，再還原轉綠。
3. 立即購買上下限：回傳購物車只有所選 SKU 一行且數量相同時得到 `/checkout`；有其他行或同 SKU 原有數量疊加時得到 `/cart?from=buy-now`。失敗案例確認 navigation callback 0 次。
4. 購物車提示：`?from=buy-now`、混合其他參數、重複 `from` 含 buy-now 時顯示；空字串、無 from、其他值不顯示。頁面掛載後直接讀 `window.location.search`，未使用 `useSearchParams()`。
5. 最愛狀態：加入與移除都先樂觀更新；非 401 失敗還原原狀並顯示 API title；401 的事件順序是先寫回 false、再執行登入導向；取消完成後再按會送 desiredState=true 加回。
6. 權限：愛心 401 共用狀態機處理，商品卡與商品頁都把目前頁面交給 `loginHrefForCurrentPage()`；列表 401 產生 `/login?next=%2Ffavorites`，測試解碼後為 `/favorites`。mock 本身無登入概念，因此 mock handler 401 案例依派工書註明不適用。
7. `priceFrom: null`：mock fixture 有一筆未定價收藏；`ProductCardLink` 的 null 分支仍畫 `FavoriteHeart`，並沿用 `suppressCardNavigation`。短暫拿掉攔截後測試轉紅，證明按心不導頁的接線測試有效。
8. `/favorites`：前置為 client mount；首載呼叫 list endpoint，自行保存 cursor；有 cursor 才顯示「載入更多」，同步 ref 防重送，末頁 cursor=null 不再載入。錯誤狀態由 `favoriteListView` 優先於空清單，空清單顯示「還沒有收藏的商品」與回首頁出口；取消只改卡片內狀態，卡片留在列表且可以再加回。
9. 360px 版面：底部列外層 `min-w-0`，摘要區 `min-w-0 flex-1 overflow-hidden`，按鈕組 `shrink-0` 且維持單列；兩顆按鈕文字未縮寫，並共用 `actionDisabled`／`actionLoading`。未改 `packages/ui`。
10. 殼：`tabs.ts` 只在「我的」的 `alsoActiveFor` 新增 `/favorites`；完整測試中 `pageShell.test.ts` 18 條與 `tabs.test.ts` 67 條皆綠，未改 `pageShell.test.ts`。
11. 事件重放：前端不接收事件，不適用；API 寫入重放以 mock 的 PUT 只留一筆、DELETE 不存在仍 204 覆蓋。
12. 禁改範圍：契約 YAML、`docs/05`、`packages/ui`、`InfiniteProductGrid`、middleware、快取設定、`me/page.tsx`、`pageShell.test.ts`、卡片 Link 包覆結構均未由 FE-32 修改；未執行 build、dev server 或禁用的 git 指令。
