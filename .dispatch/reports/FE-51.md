## 逐條自驗

### 要求 1：前台 PasswordInput

- 檔頭為 `'use client'`；props 由 `InputProps` 延伸，排除外部 `type`，`id` 必填，`autoComplete` 只接受 `current-password | new-password`；`invalid` 留在 `rest` 並轉傳。
- 結構為 `relative` 外層、既有 `Input`、絕對定位 `IconButton`；Input 加 `pr-[var(--gg-touch-min)]` 與 `[&::-ms-reveal]:hidden`，未另畫外框。
- 切換鈕明寫 `type="button"`，label 在「顯示密碼／隱藏密碼」切換，`aria-controls` 指向 id，沒有 `aria-pressed`；圖示為新增的 `IconEye`／`IconEyeOff`。
- 元件始終只渲染一個 `<Input>`。切換純函式先保存選取、直接改 DOM `type`、還原選取、聚焦，handler 最後才 `setVisible`。
- capture submit listener 會直接把 DOM type 切回 `password` 再更新 state；沒有 form 時不掛 listener，卸載會移除。
- 三個可測純函式均以 `password` 開頭；兩個使用者可見字串集中在檔案頂端模組常數；已由 root barrel 匯出。

### 要求 2：後台 PasswordInput

- 與前台各自實作，沒有 import 前台元件；同樣使用 `'use client'`、單一 input、相同 DOM 操作順序、submit capture 與 `password*` 純函式。
- 使用後台 `Input`，加 `w-full pr-[var(--ga-touch-min)] [&::-ms-reveal]:hidden`。
- 原生按鈕明寫 `type="button"`，使用 `absolute inset-y-0 right-0 min-w-[var(--ga-touch-min)]`，高度隨輸入框；沒有自訂 focus 樣式或 `outline-none`。
- 新增獨立 `EyeIcon`／`EyeOffIcon`，由 admin barrel 匯出。
- `admin/Field.tsx` 只讓 `InputProps` 接受 `ref`；原 JSX 與 `invalid` 處理未改。

### 要求 3：三個頁面

- storefront 登入、storefront 註冊、admin 登入各只替換密碼欄與 import。
- 三欄原有 `id`、`autoComplete`、`required`、`value`、`onChange`、註冊／後台的 `invalid` 均保留；`Field htmlFor` 未動。
- 頁面其他版面、文案與送出邏輯未改。

### 要求 4：測試與邊界

- 測試分別放在 storefront `(account)/_components/__tests__/` 與 admin `login/__tests__/`，未安裝 jsdom、testing-library 或其他套件。
- 靜態標記使用 `renderToStaticMarkup`；互動核心以假 input 測純函式；原始碼測試先移除註解。
- 邊界六類：重複與併發、金額數量上下限、事件重放、部分失敗不適用（純顯示元件，不發請求、不碰金額）；非法狀態由 T6 覆蓋；權限不適用（登入前頁面）。
