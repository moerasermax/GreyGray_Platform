## 逐條自驗

### 要求 1：NavDrawer

- 新增 UI 層 `NavDrawer`，props 含 `open`、`onClose`、`id`、`title`、`closeLabel`、`children`，沒有依賴 Next Link。
- portal 到 body；關閉時保留節點並套用 `inert`、`aria-hidden`；面板具 dialog／modal 語意、左側位移動畫、token 寬度與內部 overscroll containment。
- 重用既有 focus trap；呼叫端 `closeMenu` 是 `useCallback`。
- 捲動鎖只操作 `document.documentElement.style.overflow`，cleanup 還原原值；純函式由 UI barrel 以 `navDrawer...` 名稱提供。
- UI barrel 在 Dialog 後匯出 NavDrawer；圖示庫新增符合 BaseIcon 規格的 IconMenu。

### 要求 2：MobileNavMenu

- 觸發按鈕具有 `type="button"`、開啟選單標籤、expanded／controls 語意與 token 44×44 下限。
- 不呼叫 `useRouter`；pathname 為 null 時可 SSR 靜態渲染。
- 點連結、pathname 改變、matchMedia 進入 1024px 以上三種情況都呼叫同一個穩定 close callback。
- 商品分類、逛逛、購物指南三組有各自標題；後兩組連結順序固定，購物指南直接重用 `INFO_LINKS`。
- 所有連結有 token 44px 最小高度；目前頁採完全路徑比對後設定 `aria-current="page"`。
- 新字串集中在 `mobileNav.ts` 常數。

### 要求 3：DrawerCategories

- 公開介面固定為 `DrawerCategories({ open, onNavigate })`。
- 只有第一次 `open` 變 true 才從 client 端執行 `listCategories(browserApi())`，同一實例後續重用結果；layout 沒有取分類，也沒有使用 `serverApi()`。
- 載入狀態保留固定 `--gg-space-8` 高度；空清單或失敗回 null，分類標題也不畫。
- 成功時依 API 回傳順序連到 `/categories/{id}`，點擊呼叫 `onNavigate`。

### 要求 4：MobileSiteHeader 與掛載

- client component 使用獨立純函式規則；pathname null 回 false。
- 手機限定、sticky、header z token、top-bar 高度與 safe-area 寫法均由既有 token 組成。
- 左側選單、中間首頁品牌連結、右側同寬空位；品牌不是標題元素。
- layout 掃描測試證明掛在 `SiteHeader` 後、children 前；body 無新增屬性，SupportWidget 的 import、寫法與位置未改。

### 要求 5：首頁與頁面頂部列

- 首頁品牌前加入共用 `MobileNavMenu`。橫向 gap 從 `--gg-space-5` 收到 `--gg-space-2`，其餘列結構不變，替 360px 第一列騰出 32px。
- `TopBarRule` 新增 `showMenuButton`：商品詳情 true、購物車 true、結帳 false；頁面元件只依規則渲染，不改任何 page 檔。
- 商品詳情右側以 token gap 同時容納購物車與選單；購物車頁只顯示選單；結帳不顯示選單。
- 返回與購物車 Link 均補上 `min-height/min-width: --gg-touch-min`。

### 要求 6：消費端測試

- 沒有安裝 jsdom 或 testing-library；規則使用純函式，呈現使用 `renderToStaticMarkup`。
- `pageShell.test.ts` 的既有斷言未刪改，只新增手機頁首規則與 layout 掛載測試。
- 新增 `mobileNavMenu.test.tsx`，依 workspace classic JSX 慣例設定 `globalThis.React`。

- 三處漢堡鈕：`min-h/min-w: --gg-touch-min`＝44×44 下限。

- 抽屜關閉鈕是 button，沿用全域 button 44px 下限；抽屜每個 Link 明列 44px 最小高度。
