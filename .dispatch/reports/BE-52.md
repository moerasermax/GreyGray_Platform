## 逐條自驗

### A. migration

- 新增 `0019_catalog_favorite.sql`，順序為 `BEGIN` → `SET ROLE greygray_owner` → 建表／索引 → `RESET ROLE` → catalog schema owner 斷言 → `COMMIT`；沒有 `GRANT`。
- `catalog.favorite` 有複合主鍵、同 schema 商品複合外鍵與 `ON DELETE CASCADE`、兩個非零 UUID CHECK、四欄 `NOT NULL`、指定的倒序索引；沒有跨 schema 外鍵。
- 正式 migration 測試跑 0001→0019 兩次，查 `pg_constraint` 驗證主鍵／外鍵／CHECK，驗證 owner 與 `greygray_catalog` 權限，並在 `SET ROLE greygray_catalog` 後實際 INSERT／SELECT／DELETE。
- 負向 counterexample：測試刻意建立錯誤 owner 的 catalog table，再執行 0019，確認 owner 斷言以 `P0001` 變紅，最後清除測試表。

### B. Catalog 模組

- 新介面命名為 `IStorefrontFavorites`，提供加入、移出、列出、批次查詢；`Catalog.Contracts` 只新增對 `Identity.Contracts` 的 DAG 方向參考。
- tenant 只從 `ICorrelationContext.TenantId` 取得；時間只從 `IClock` 取得。
- 加入前以商品上架且至少一個 SKU 上架判斷可見性；重複／併發使用 `INSERT ... ON CONFLICT DO NOTHING`，不先查 favorite，重複加入不更新 `created_at`。
- 清單在 SQL 分頁前套可見條件，依 `(created_at DESC, product_id DESC)` keyset 分頁；專用 24-byte cursor 同時編碼 UTC ticks 與 product id，後續頁以 EF 已映射的 `ProductId` 比較，沒有取 `.Value` 造成 Npgsql 無法翻譯。
- 商品清單與收藏共用投影算法；收藏允許未定價現貨且 `PriceFrom` 為 null。空商品 id 集合直接回空集合、不查資料庫。

### C. Storefront Host

- 新增 GET／PUT／DELETE `/v1/me/favorites`；三條匿名均 401，非法 product id 為 404；PUT／DELETE 使用既有 idempotency helper 並成功回 204。
- HTTP 測試涵蓋同 key 重送、不同行為 key 的真 barrier 同時請求、同 key in-flight 409、缺／過長 key 的既有 helper 行為，以及 GET 的 200/401/422/空頁形狀。
- `/products` 與 `/products/{id}` 已填真實 `isFavorited`：登入一頁批次查一次；匿名固定 false 且 fake 斷言 favorite 查詢次數為零。
- 收藏 GET 走共用頁面投影，預購商品的 `campaignId`／`priceFrom` 有 HTTP 層斷言；OpenAPI components 的 idempotent／paged endpoint 清單已補齊。

### D. 邊界測試六類與組合根

- 0 migration：正式 migration chain、冪等、owner、constraint、default privilege、實際角色 CRUD 與錯誤 owner counterexample 均有測試。
- 1 重複與併發：循序重複、不同 key 真 barrier 併發、同 key in-flight、單列與 created_at 不變均有測試。
- 2 上下限：limit 0／101、亂 cursor 都回 `catalog.invalid-cursor`／422；空清單為 `items: []`、`nextCursor: null`。
- 3 非法狀態：不存在、商品下架、全 SKU 下架不可加入；下架時收藏不刪、清單隱藏、DELETE 仍成功、重新上架行為；未定價上架現貨可列且 null price。
- 4 權限：三端點匿名 401；customer 與 tenant 隔離；匿名商品回 false 且沒有 favorite DB 呼叫。
- 5 事件重放：不適用，本包沒有發送或接收整合事件。
- 6 部分失敗與分頁：固定同一 `IClock`、limit 1 翻三頁無重複遺漏；可見／不可見交錯仍滿頁；翻頁途中下架不會少掉其他項目。
- 7 組合根：`AddCatalogModule` 後可解析 `IStorefrontFavorites`，新增服務只用三個 Host 都已具備的相依。

資料庫行為測試選擇：migration 本身放在 `GreyGray.M1a.Migrations.Tests`；Catalog favorite 整合測試放在 `GreyGray.M1a.IdentityCatalog.Tests` 的獨立正式 migration-chain fixture。沒有修改 `IdentityCatalogTests.SchemaSql` 手寫 schema。

### E. 不要做與 §5 停止條件

- `docs/api/*.yaml`、`docs/05-API契約.md`、前端、`ops/`、其他模組均零變更；沒有 integration event、訪客收藏、收藏上限／統計、migration GRANT 或手動啟動 dev Host。
- `SET ROLE` 權限、Contracts DAG、共用投影、SQL 可見規則都能依派工書落實，沒有撞到 §5 要停止詢問的條件；下架不刪收藏依 ADR-036 保留。

## 我發現但沒做的事
