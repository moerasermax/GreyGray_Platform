## 逐條自驗

派工書 §5 的五條「可能寫錯的地方」：

**1．`listShipments({ limit: 100 })` 只拿第一頁，不要假裝是完整清單**
兩處呼叫都留了註解寫明這是刻意的取捨（`orders/[orderId]/page.tsx` 新 effect 上方、
`CreateShipmentDialog.tsx` 新 effect 上方）。
訂單頁**多做了一件事**：把 `page.nextCursor != null` 存成 `shipmentsTruncated` 傳進區塊，
真的有下一頁時畫面會多一行「只讀了出貨單列表的第一頁，若這張訂單有更早的出貨單，
上面的張數可能不完整」——這樣「掛了 3 張」才不會在有第二頁時變成謊話。
測試 `還有下一頁時明講張數可能不完整，不假裝是總數` 釘住這一條。
（對話框那邊的張數只是提示、少算不擋操作，所以沒做同樣的標示，註解裡寫了理由。）

**2．狀態值用 enum 字串不要用數字**
`CLOSED_FOR_SHIPPING` 是 `Set(['Shipped','Completed','Cancelled'])`，
`deliveredCount` 比對 `status === 'Delivered'`，全部是 api-client 產出的字串型別，
沒有任何數字對照。測試 `canCreateShipmentForOrder 逐個狀態` 逐個點名。

**3．標籤與 tone 用 `shipments/_lib/labels.ts` 現成的**
`OrderShipmentsSection.tsx` 直接 import `shipmentStatusLabel`／`shipmentStatusTone`／
`shipmentMethodLabel`，訂單頁沒有重寫任何一份。測試裡斷言畫出「草稿／已送達／已交運／
宅配到府／超商取貨」，就是那支模組回的字——哪天有人在訂單頁另開一份會對不上。

**4．新區塊失敗不能把整頁變成錯誤頁**
出貨單走自己的 effect 與自己的 `shipmentsFailed` state，`catch` 只設這個旗標，
不碰頁面層的 `error`（頁面層 `error` 一被設就會 return `<ErrorState />`）。
區塊自己顯示「讀取出貨單失敗，這一區塊暫時看不到；訂單本身的資料不受影響」＋「重試」。
測試 `讀失敗時只有這一區塊講失敗，不畫任何張數` 釘住。

**5．一張出貨單可能同時掛好幾張訂單**
過濾一律是 `shipment.orderIds.includes(orderId)`（`shipmentsOfOrder`），
`countShipmentsByOrderId` 也是把每張出貨單的 `orderIds` **逐個**記到各自訂單頭上。
兩條測試專門驗合併出貨：`shipmentsOfOrder` 那條讓同一張出貨單在兩張訂單下都算得到，
`countShipmentsByOrderId` 那條驗合併的一張兩邊各記一次。畫面上還多標了
「與其他 N 張訂單合併出貨」。

## 我發現但沒做的事

1. **「已有 N 張出貨單」的 N 依賴 `listShipments({ limit: 100 })` 的第一頁，會低估。**
   出貨單累積超過 100 張之後，舊訂單的標示可能顯示 0 張或偏少。這只是提示、不擋任何
   操作，所以照派工書用前端過濾；但訂單頁那邊我加了 `nextCursor` 的「可能不完整」提醒，
   對話框沒加（一列一個 badge 塞不下，而且它不是使用者拿來做判斷的唯一依據）。
   要根治得靠 `GET /v1/shipments` 加 `orderId` 篩選——§0.4 明講這一包不做，我沒做。

2. **`Returned`（已退回）與 `Lost`（已遺失）我算成「還沒簽收」。**
   派工書沒有明講這兩個狀態怎麼算。我選擇與後端一致（`RecordShipmentDeliveredAsync`
   比對的是 `Delivered`），所以有一張退回時訂單頁會說「還有 1 張沒有簽收；全部簽收後
   訂單才會轉為已出貨」——這句話**在事實上是對的**（那張訂單確實永遠不會自己轉已出貨），
   但對操作的人可能不夠：他真正需要知道的是「這張退回了，要重開一張」。
   這需要決定業務動作（退回後是否自動開新出貨單、或允許人工結案），**超出這一包的範圍，
   我沒有自己決定**。目前的做法是狀態徽章照實顯示「已退回」，讓人看得到。

3. **對話框裡搜尋後被過濾掉的訂單，若先前已勾選，選取仍然保留。**
   這是既有行為（`selectedOrderIds` 不隨 `orders` 變動而清理），我沒有改——
   修它會動到勾選的語意，不在必做範圍。實務上不容易撞到（勾完通常就直接送出）。

4. **`apps/admin` 的訂單列表頁（`orders/page.tsx`）沒有加出貨單資訊。**
   派工書只點名訂單**詳情**頁，我就只改詳情頁。列表頁若也想看「還差幾張」，
   要多打一次 `listShipments` 並在每一列算，值不值得由整合者決定。
