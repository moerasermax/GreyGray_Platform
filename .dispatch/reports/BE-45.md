## 逐條自驗

### 必做 A　START 改看 SCM 狀態

- **A-1** `ops/lib/Deployment.ps1` 新增 `Wait-ManagedServiceStart`：參數 `-ServiceName`、
  `-StartService <scriptblock>`、`-GetStatus <scriptblock>`、`-TimeoutSeconds`
  （`[ValidateRange(5, 180)]`）、`-PollMilliseconds`（預設 500）。
  先呼叫 `-StartService`（**完全不看 ExitCode**，只把 ExitCode／StdOut／StdErr 留著給訊息用），
  再輪詢 `-GetStatus`：`Running` → 回 `[pscustomobject]@{ ServiceName; Status; StartExitCode; Elapsed }`；
  其他狀態繼續等；到期 throw，訊息含服務名、最後狀態、nssm 的 ExitCode 與輸出。
  `Stopped` 一路到期也 throw（**exit 0 不算綠**）；ExitCode ≠ 0 但最後 Running 時
  `Write-Host` 一行 `⚠` 警告並把 nssm 原話印出來，**不 throw**。
- **A-2** `ops/deploy.ps1` 原第 472-475 行改成逐一 `Wait-ManagedServiceStart`：
  `-StartService { Invoke-Nssm -Arguments @('start', $serviceNameForStart) -AllowNonZeroExit }`、
  `-GetStatus { $serviceForStatus = Get-Service -Name $serviceNameForStart; $serviceForStatus.Refresh(); $serviceForStatus.Status }`、
  `-TimeoutSeconds $HealthTimeoutSeconds`。兩個都是 **plain scriptblock**，迴圈變數先複製成
  `$serviceNameForStart`（照第 405-425 行 `$serviceNameForGet` 的既有做法）。
  `$restartBoundaryUtc` 仍在 START 之前取，位置沒動（現為第 491 行）。
- **A-3** `nssm start` 一律帶 `-AllowNonZeroExit`，由第 19 項 AST 釘住（負向測試見「指令與輸出」④a）。
- 真正的綠燈仍是 `Assert-NewApplicationProcess`，一行都沒改。

### 必做 B　部署期間暫停 watchdog

- **B-1** `Suspend-WatchdogTask`（`-TaskName`／`-GetTask`／`-StopTask`／`-DisableTask`）與
  `Resume-WatchdogTask`（`-TaskName`／`-Suspended`／`-EnableTask`）都放在 `ops/lib/Deployment.ps1`，
  決策邏輯全部吃注入的 scriptblock。`Suspend`：查不到任務 → 回 `$false`、不 Stop 不 Disable；
  `State -eq 'Running'` → 先 `-StopTask` 再 `-DisableTask`；其他 → 只 `-DisableTask`；回 `$true`。
  `Resume`：只有 `-Suspended $true` 才 `-EnableTask`。
- **B-2** `deploy.ps1` 在原第 327 行 `$oldTokens = …` 之前呼叫 `Suspend-WatchdogTask`

  （原 327-538）包進 `try { … } finally { Resume-WatchdogTask … }`（`finally` 現為第 586-589 行）。
  傳的是真的 `Get-ScheduledTask`／`Stop-ScheduledTask`／`Disable-ScheduledTask`／`Enable-ScheduledTask`。
- **B-3** 最後的 `Register-ScheduledTask -Force` 留在原位、在 `finally` 之後，一個字沒改。

### 派工書 §5「可能寫錯的地方」逐條

1. **`ServiceController.Status` 是快取，輪詢前一定 `Refresh()`** ——
   `deploy.ps1` 的 `-GetStatus` scriptblock 每次都是 `Get-Service` → `.Refresh()` → `.Status`，
   而且是每次呼叫都重新 `Get-Service`。沒有用 `WaitForStatus`（5.1 與 7 的逾時例外型別不同），
   自己輪詢，訊息可控。
2. **nssm 輸出夾 NUL** —— `Wait-ManagedServiceStart` 有 `Get-PrintableNativeText`
   把 `[char]0` 濾掉，但**只用在組錯誤訊息與警告**。成功條件只有 `Status -eq Running`，
   **完全沒有任何字串比對**。self-test 的假輸出刻意夾了 NUL（(a) 尾端一個、(c) 前後各一個），
   兩個 runtime 都過。
3. **self-test 不准呼叫真的 `*-ScheduledTask`** —— 第 20 項四個假 scriptblock 只往
   `ArrayList` 記錄字串，沒有任何 `*-ScheduledTask` 指令；`deploy.ps1` 那邊才傳真的 cmdlet。
4. **`Disable` 之後 `Register-ScheduledTask -Force` 會重登記為啟用，兩者不衝突；
   失敗路徑只有 `finally` 會跑** —— `Resume` 就放在 `finally`，`Register` 留在 `finally` 之後原位，
   AST 釘住「`Resume` 一定在 `finally` 內」（負向測試見 ④b）。
5. **迴圈變數複製一份給 plain scriptblock（`$serviceNameForGet` 的模式），不准 `GetNewClosure()`** ——
   新的 `$serviceNameForStart` 照抄那個模式；第 18 項（AST 掃 `GetNewClosure`）在兩個 runtime 都還是 0 個。
