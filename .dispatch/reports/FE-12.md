### 1. 🔴 開發環境缺三項設定，Identity 與 Payment 整組不能用

`ops/start-dev-hosts.ps1` 只餵 `ConnectionStrings__*`，缺：

| 設定鍵 | 缺了會怎樣 | 實測 |
|---|---|---|
| `Identity:DataProtectionKey` | `/v1/auth/login`、`/v1/auth/register`、`/v1/me` 全 500（兩個 Host 都是） | 上面③⑤ |
| `Payment:ECPay:MerchantId`（連帶 `HashKey`／`HashIV`） | `/v1/cart`、`/v1/orders/{id}/payment` 500 | 上面⑤ |

`InvalidOperationException`，被 `ExceptionHandlerMiddleware` 轉成 500。
**FE-12 的第 2、3、4 條全部卡在這裡。**

補上金鑰之前要先想清楚一件事：`iam` 的 ciphertext 欄位是用這把金鑰加密的，
現在 `iam.customer` 已經有 1 筆（BE-22 驗收時留下的）。臨時金鑰寫進去的資料，
之後換成正式金鑰就解不開了。這是為什麼我沒有自己補一把跑下去。

### 2. 🔴 資料庫沒有任何種子資料，而且員工帳號無法建立

`iam.staff_account` = 0，catalog／campaign／ordering 全部 0（見第 8 節）。
`CreateStaffInput` 只有型別、沒有任何 Host 端點或 ops 工具呼叫它。

### 3. 🔴 admin BFF 的三組端點會永久不回應（不是慢，是不回）

```
$ curl -m 25 http://127.0.0.1:5001/v1/orders

`/v1/orders`、`/v1/orders/{id}`、`/v1/campaigns`、`/v1/shipments` 都一樣。

就佔住一個連線不放。**優先度我放跟①②同級。**

### 4. 🟠 `middleware.ts` 的導向永遠指向 `localhost`，正式機會導到使用者自己的機器

```
$ curl -H "Host: admin.greygray.tw" http://127.0.0.1:5013/orders
Location: http://localhost:5013/login?from=%2Forders

$ curl -H "Host: example.invalid" ...
Location: http://localhost:5013/login?from=%2Forders

$ curl -H "Host: admin.greygray.tw" -H "X-Forwarded-Proto: https" ...
Location: https://localhost:5013/login?from=%2Forders   ← proto 有吃，host 沒有
```

原因在 standalone `server.js` 內嵌的設定：`"trustHostHeader": false`。
Next 不信任 Host header 時，middleware 裡 `request.url` 的 origin 會退回
`localhost:PORT`，而 `NextResponse.redirect(new URL('/login', request.url))`
產出的就是絕對網址。

`ops/deploy.ps1:215` 部署時是 `HOSTNAME=127.0.0.1` ＋ cloudflared 反向代理
（`ops/deploy.ps1:222` 的註解「不要把 BFF listener 暴露到 LAN」），
所以**正式機上任何未登入的人打後台任何頁面，都會被導到 `https://localhost:5003/login`——
那是他自己的電腦，登入頁根本開不起來。整個後台會登入不能。**

修法在 `apps/admin/next.config.ts`（`experimental.trustHostHeader`）或
反向代理改寫 Location，**兩個都不在 FE-12 的 allow**，所以我只記錄。
建議實際上線前用 `curl -H "Host: <正式網域>"` 複驗一次。

`src/Hosts/GreyGray.Api.Storefront/Program.cs` 裡 `grep -n "Cors"` 是空的；
共用層（`src/Shared/`、`src/Platform/`）也沒有。實測：

```
$ curl -X OPTIONS http://127.0.0.1:5001/v1/auth/login -H "Origin: http://127.0.0.1:5003" \

前台是 5002、storefront BFF 是 5000（`docs/05` §表格），**是不同來源**；
而 `apps/storefront/app/_lib/apiClient.ts` 的 `browserApi()` 是讓瀏覽器直接打
`NEXT_PUBLIC_API_BASE_URL`，不是走 Next 的 route handler 代理。
所以購物車、結帳、登入、註冊、儲值金、訂單這些 client 端頁面，
**在真的瀏覽器裡一個都不會成功**——我這一輪用 curl 打不會踩到，因為 curl 不執行 CORS。

Lax cookie 在跨站 XHR 上根本不會送出。如果正式機上前台與 BFF 不是同一個
registrable domain，補了 CORS 也還是不會帶 cookie。**這件事要跟後端一起決定
拓樸（同網域路徑分流 vs 子網域），不是單純補一行 `AddCors`。**
