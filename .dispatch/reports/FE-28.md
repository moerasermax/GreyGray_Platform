## 逐條自驗

**必做 A — 純函式 `subtotalPreview`**　✅
`frontend/apps/storefront/app/_lib/subtotalPreview.ts`，簽名 `(price: Money, quantity: number): Money`，回 `{ amountMinor: price.amountMinor * quantity, currency: price.currency }`。守衛：`quantity` 不是 ≥ 1 的整數 → `RangeError`；`amountMinor` 不是 ≥ 0 的整數 → `RangeError`；**不回 0 湊數**。檔頭註解寫明 ADR-033：只用於顯示、不送後端、不存任何地方、購物車以後端為準、其他頁面不准照抄。
測試 14 條：60×5＝300、數量 1、幣別原樣（JPY）、0 元 × 7、不就地改動入參、數量 0／負／小數／NaN／Infinity throw、金額負／小數／NaN throw、超出安全整數 throw。

**必做 B — 底部列「N 件 · 小計」**　✅
新檔 `_components/BottomBarSummary.tsx`（props：`quantity`、`price`、`unitPriceLabel`），純呈現、沒有 state。第一行 `{quantity} 件 · {unitPriceLabel ?? formatMoney(price)}`（小字），第二行「小計」標籤 ＋ `PriceDisplay size="lg"`。`!price` 時回一個空的 `<div className="flex flex-col" />`（維持 flex 版位，不出現任何金額字樣），按鈕的 `disabled` 邏輯一個字沒動。`AddToCartPanel` 只傳 state 進去。

## 我發現但沒做的事

1. **預購沒定價時，同一畫面會出現兩種說法。** `UnitPriceBlock` 依必做 C 顯示「售價在開團時決定」，而面板下方既有的 `disabledReason`（`AddToCartPanel.tsx:55-61`）在 `!hasPrice` 時一律顯示「這個規格尚未定價，請稍後再試。」——不分預購或現貨。所以預購未定價的商品，上面寫「開團時決定」、下面寫「尚未定價，請稍後再試」。必做 C 同時要求「跟既有 `disabledReason` 文案一致，不要兩種說法」與「預購顯示『售價在開團時決定』」，這兩句在預購情境下互斥。
   我照字面實作（預購用新文案、現貨用舊文案），**沒有**去改 `disabledReason`——那會動到加入購物車的判斷區塊，超出必做 C 的範圍。要收斂的話有兩條路，請 Leader 挑：(a) `disabledReason` 在 `isPreorder && !hasPrice` 時回 `null`（上方已經說明了）；(b) 資訊區改成也用「尚未定價」那一句，放棄預購專用文案。現貨情境沒有這個問題（兩處同一句，只是重複一次）。
   **→ 第二輪已依 Leader 裁決收斂為 (a) 的變形：`AddToCartPanel` 算 `noPriceMessage`、`disabledReason` 在 `!hasPrice` 時回 `null`，說明只出現在資訊區一處。這一項已解。**

2. **多加了一個守衛：相乘後不是安全整數就 throw。** 必做 A 只列了「數量 ≥ 1 整數」「金額 ≥ 0 整數」兩個。我加了第三個（`Number.isSafeInteger(amountMinor)`），理由是這一包的整個重點就是「不要讓錯的金額看起來像對的」——超過 2^53 的乘積會靜靜失真，長在畫面上就是一個看起來正常的數字。不是換做法，是同一條原則的延伸；若 Leader 認為超出範圍，刪掉那三行與對應的 1 條測試即可（其餘 13 條不受影響）。

3. **`BottomBarSummary` 沒價格時回的是空 `<div className="flex flex-col" />` 而不是 `null`。** 這是為了讓 `justify-between` 仍把「加入購物車」按鈕推到右邊；回 `null` 會讓按鈕整個滑到左側。測試有守著「不出現任何金額字樣」。

4. **沒有跑真瀏覽器。** §4 第 3 條（正式站上單價 NT$60、5 件 → 小計 NT$300、購物車金額仍來自後端）我碰不到——dev server 由 Leader 管、正式站要部署後才驗。這一條**沒有自驗**，不要當成已驗。

5. **`unitPriceLabel` 在底部列取代了單價本身。** 既有版本是「大字單價 ＋ 小字包裝單價」兩個都畫；新版第一行是 `N 件 · (unitPriceLabel ?? formatMoney(price))`——有包裝單價時就只畫包裝單價（它本身開頭就是 `NT$60／…`，含單價）。這是必做 B 字面上寫的「有 `unitPriceLabel` 就用它」，先照做，但畫面資訊量與舊版略有不同，Leader 過目一下。
