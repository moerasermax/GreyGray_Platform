## 逐條自驗

### §1 要做的事

1. 已由 OpenAPI 重生 storefront/admin 型別；指定的新契約型別與 409 code 均存在，產物未手改。
2. 新增 `paymentInstructions.ts`：`undefined` 與 `null` 同視為無取號資訊；三種方式與未知方式的顯示資料、台北期限、結果頁／發動頁／詳情頁判斷均為純函式。`formatDateTimeInTaipei`、`copyText` 已一般化，舊 `formatPlacedAtInTaipei`、`copyOrderNumber` export 保留。
3. 新增只吃 props 的 `PaymentInstructionsCard`：ATM、超商代碼、條碼三種文案與欄位齊全；應繳金額直接格式化後端 `grandTotal`；條碼只輸出三段文字；複製鈕使用 `--gg-touch-min`，回饋在獨立 `aria-live`。
4. 付款結果頁有取號資訊時停止輪詢，標題為「已產生繳費資訊」，隱藏兩段確認文案、重新付款、重新查詢與 `PriceDisplay`，保留訂單入口；無取號資訊時維持原流程並加入資訊晚到提示；期限改台北時間。
5. 付款發動頁先讀訂單；有取號資訊不呼叫付款、不送表單；401 導登入，其他讀取錯誤照常付款；`payment.instructions-already-issued` 重讀訂單，有資訊顯示卡、仍無資訊顯示既有錯誤狀態；提供訂單明細與首頁出口。
6. 訂單詳情有取號資訊時 `canPay=false` 且顯示取號卡；倒數改由 `AwaitingPayment + paymentDueAt` 決定，取消訂單規則未動；付款 409 改重讀；下單時間改台北時間。
7. `PaymentCountdown` 在 ≥24 小時顯示天數，24 小時內維持時分秒，並顯示台北絕對期限；5 分鐘紅字規則未動。
8. mock `OrderSeed` 支援期限與取號資訊；ATM 種子接在陣列最後，`paymentDueAt === paymentInstructions.expiresAt`，沒提供種子的既有 2 小時行為維持。

### §3 T1～T9

- T1：有值 `true`；`null`、省略欄位（runtime `undefined`）均 `false`。
- T2：ATM／超商代碼／條碼的標籤、值、複製旗標、含運總額與台北期限均有固定輸入測試；`2026-10-04T15:59:59Z → 2026/10/04 23:59（台灣時間）`；未知 method 不丟例外並顯示通用句。
- T3：三種卡片均以 `renderToStaticMarkup` 驗文案與欄位；測得複製鈕最小高度 token、獨立 `aria-live`、條碼順序；負向違規注入證明圖片守衛會變紅。
- T4：純函式驗有取號資訊時停止輪詢、使用指定標題，並關閉確認文案、兩個重試入口及金額；無取號資訊維持原旗標。
- T5：純函式驗初讀有資訊不發動、初讀 401 登入、其他錯誤發動；409 重讀，有資訊顯示卡、仍無資訊轉錯誤狀態。
- T6：純函式驗有資訊 `canPay=false`、倒數仍顯示；409 判定為重讀，其他 409 不誤判。
- T7：`2 天 23:59:59`、剛好 `1 天 00:00:00`、`23:59:59`、歸零與 5 分鐘邊界均已測；元件靜態渲染含台北絕對期限。
- T8：既有付款結果摘要 12 tests 全綠，舊台北時間與複製 API export／呼叫點行為維持。
- T9：`pnpm typecheck`、`pnpm test`、storefront build 均 exit 0；條數見上節。

### 邊界六類

- 上下限：已測剛好 24 小時、24 小時少 1 秒、5 分鐘與歸零；未知 method 有 fallback。
- 非法狀態轉移：已測已取號再付款的 `payment.instructions-already-issued` 重讀分支。
- 重複與併發：複製 helper 每次獨立呼叫；卡片重複點擊會取消並重設同一個回饋 timer。付款併發由後端 409 契約收斂，前端不開新單號。
- 權限：初讀／付款／409 重讀的 401 均導登入；本包未新增權限規則。
- 事件重放：不適用；本包不處理 webhook 或事件，只讀後端訂單投影。
- 部分失敗：已測初讀訂單非 401 失敗仍可發動付款；409 後重讀仍無取號資訊落回錯誤狀態。
